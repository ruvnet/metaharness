# ADR 317: Independent review context isolation

Status: Proposed

Date: 2026-09-24

Issue: #351

## Context

MetaHarness relies on role separation across research, implementation, review, security, testing, reproducibility, and release. Role labels alone do not create independence if a reviewer can observe the worker trajectory, peer messages, previous verdicts, reward history, shared scratchpads, or identity cues.

`Emergent Collusion in Long Horizon LLM Agent Interaction` (arXiv:2609.24967, submitted 2026-09-21) reports collusion in 93.6% of trajectories overall across ten models in a repeated task and peer verification environment. The reported mitigation with the clearest effect is reducing cross episode interaction history. Evidence class is originating team measurement with public code and dataset, not an independent MetaHarness reproduction.

The result does not prove that current MetaHarness reviewers collude. It invalidates the assumption that separate model calls or separate role names are sufficient independence controls.

## Decision

Add a small evidence only boundary to `@metaharness/flywheel`: `IndependentReviewPacket`.

The packet:

1. binds review, run, tenant, candidate, task, policy, evaluator, and generic reviewer role;
2. contains only typed content addressed evidence references;
3. rejects unknown top level and evidence fields;
4. rejects unknown evidence classes;
5. excludes worker reasoning, peer messages, prior verdicts, reward history, shared scratchpads, and reviewer identity by schema;
6. bounds evidence count and total declared bytes;
7. sorts evidence before hashing so packet bytes are deterministic;
8. expires;
9. carries `authority: none`;
10. verifies expected tenant, candidate, task, policy, evaluator, and role before use.

The packet does not authorize promotion, execution, deployment, credential access, or protected test access.

## Trust boundary

The packet proves only what was admitted into the packet. It does not prove that a host process withheld other state from the reviewer. A production review runner must create a fresh reviewer context, materialize only evidence references present in a verified packet, deny shared memory and peer message surfaces, and keep protected evaluator state outside model context.

RVM remains the effect authority. Promotion remains a separate MetaHarness gate requiring human approval.

## Allowed evidence classes

* artifact
* specification
* test_result
* benchmark_result
* security_scan
* reproduction_receipt
* source_reference
* policy_reference

Adding a new class requires an explicit code and review change. Natural language generated by a candidate is not promoted to a new evidence class dynamically.

## Rejected alternatives

### Prompt only independence

Rejected because the cited experiment demonstrates emergent behavior under repeated interaction. A prompt telling a reviewer to ignore peer influence leaves the influence channel present.

### Full trajectory with a classifier

Rejected because classifier quality becomes a second opaque trust dependency and can miss latent reciprocity signals or identity cues.

### Remove all history

Rejected as the only mechanism because reviewers still need artifacts, specifications, tests, benchmark outputs, and provenance. The packet keeps necessary evidence while removing social and reward channels.

### Share prior verdicts for efficiency

Rejected for independent review. Prior verdicts may be used by a later aggregation stage after independent reviewers have committed their own receipts.

## Security invariants

1. Unknown fields fail closed.
2. Packet evidence is reference based, not free form peer prose.
3. Packet digest covers every admitted field.
4. Evidence identifiers are unique.
5. Evidence kinds are allowlisted.
6. Total declared evidence bytes are bounded.
7. Tenant, policy, evaluator, candidate, task, and role substitution fails verification.
8. Expired and not yet valid packets fail verification.
9. Authority is always `none`.
10. A reviewer packet can never mutate acceptance tests or grant a capability.

## Benchmark contract

Structural benchmark uses five deterministic seeds and 10,000 cases: 4,000 clean and 6,000 adversarial. Adversarial families cover forbidden context, unknown evidence class, duplicate evidence identifier, evidence budget exhaustion, tenant substitution, and evaluator substitution.

Report baseline and candidate acceptance, false acceptance, false denial, total and batch latency, p50 and p95 batch latency, throughput, environment versions, seeds, sample size, cost, energy availability, and reproduction command.

Structural acceptance requires zero malicious acceptance, zero clean denial, and deterministic packet digests.

Behavioral promotion is separate. Issue #351 freezes four evaluator context arms and requires at least 80% relative reduction in collusive or reciprocity driven false acceptance, zero protected security regression, clean candidate acceptance within 3 absolute points, and review cost increase below 15% unless offset by at least 5 absolute points lower false acceptance.

## Rollback

The feature is additive. Rollback removes exports and the new source, test, benchmark, workflow, and documentation files. No stored data migration is required. Existing flywheel receipts and promotion lineage are unchanged.

## Cross stack mapping

Core Memory stores the packet and behavioral reproduction evidence but does not reinterpret reviewer context as memory authority. RuVector and RuVector WASM may retrieve allowed evidence references under tenant scope. RuFlo creates fresh reviewer jobs and denies peer history surfaces. MetaHarness owns packet construction, verification, independent evaluation, and promotion. RVM remains effect and capability authority. RVF can bind packet digests into release evidence. RVForge packages only accepted integrations. Autogenous and Dream Machine may propose candidates but do not select reviewer context. MidStream records review lifecycle boundaries. RuView, RuField, and WorldGraph can reuse isolated verification for sensing and spatial artifacts. LatentMesh transports packets as untrusted evidence. Cognitum can expose isolated review as an enterprise assurance property. MCP servers may supply evidence references but cannot add evidence classes or authority. Distributed infrastructure must enforce process and storage isolation beyond the structural packet.

## Commercial implication

Independent review is a prerequisite for defensible autonomous software delivery. The product claim should be narrow: MetaHarness can create provenance bound minimal reviewer inputs. A stronger claim that reviews are behaviorally independent requires the frozen reproduction in #351.
