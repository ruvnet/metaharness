## OBSERVATION

`packages/create-agent-harness/src/score.ts`'s `scorePublishReadiness()`
gated its 20-point "npx-runnable" bonus on `manifest?.host && pkg?.bin`.
`HarnessManifest` (`manifest.ts`) has never had a `host` field — only
`hosts: string[]` — so this condition was unreachable in production;
every scaffolded harness with a `bin` entry fell to the 10-point
`pkg?.bin`-only branch regardless of how many hosts it declared. The
sibling `scoreRepoUnderstanding()` had the mirror bug: `manifest.host ||
manifest.hosts` credited "host(s) declared" for `hosts: []` too, since an
empty array is truthy in JavaScript. Confirmed live by direct source
inspection (`grep -n "manifest.host" packages/create-agent-harness/src/manifest.ts`
returns zero matches for a `host` field) and by a new test suite
(`score-host-detection.test.ts`, previously nonexistent for this scorer)
that fails non-vacuously against the pre-fix code.

An independent adversarial critic (no shared authorship context)
additionally confirmed via full-repo grep that no other file writes or
reads a singular `manifest.host`, so the fix cannot regress any legitimate
real-world manifest shape.

## MEASUREMENT

- **Fix**: replaced both conditions with `Array.isArray(manifest.hosts) &&
  manifest.hosts.length > 0`.
- Red/green: 4/7 new tests fail pre-patch with exactly the values the bug
  predicts (e.g. Publish-readiness `30` instead of `40` for a `bin` +
  one-host fixture); 7/7 pass post-patch.
- Full `create-agent-harness` suite: 554→561/561 passed (2 skipped
  unchanged, 43→44 files), **0 regressions**, `tsc --noEmit` clean.
  Sibling `genome-scorers.ts` suites (39 tests) unaffected.
- **Live CLI smoke test** (real harness scaffolded via `npx metaharness
  smoke-harness --template minimal --host claude-code`, built
  `dist/harness-bin.js`, not mocks): `harness score` on that fixture went
  Publish-readiness `30→40`, overall `65/100→66/100` pre/post-fix.
- **Independent critic** (fresh sub-agent): re-ran everything above from a
  cold read, reproduced identical numbers, verified the new tests are
  non-tautological (expected totals hand-derived from the scorer's own
  point values, not compared to the implementation), and returned
  **ACCEPT**.

## INFERENCE

This is the same bug *class* — presence/field-reference checks standing in
for verified signal — that three prior `generator-genome` nights (08-15,
08-25, 08-30) already closed in the sibling `genome-scorers.ts` file. 2026
research (Harness-Bench arXiv:2605.27922; the 64.8%-zero-coverage-PRs study
arXiv:2607.18057; Factory.ai/kodustech's content-aware readiness checks)
independently converges on the same principle: a scaffolding scorer that
checks for a field's *presence* rather than its *correctness* systematically
overstates readiness. `score.ts` reimplements similar dimensions to
`genome-scorers.ts` under a different name and had never received the same
hardening — this fix extends the already-validated pattern to the sibling
file rather than inventing a new one.
