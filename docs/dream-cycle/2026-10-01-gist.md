# flywheel-promotion SOTA Report — 2026-10-01

TL;DR: `verifyMultiGenerationEvidence` (PR #358, merged 2026-09-27, unaudited by any
Dream Cycle night until tonight) compares IEEE-754 floating-point deltas against
`DEFAULT_MULTIGEN_POLICY`'s "frozen thresholds" using strict `<`/`>=`. A generation
whose improver yield improves by exactly the policy minimum (1 extra success out of
20 attempts — a realistic small-N case) can be incorrectly rejected because
`3/20 - 2/20 === 0.04999999999999999` in JS, a few ULPs short of `0.05`. Fixed with a
float-safe threshold comparator (`THRESHOLD_EPS = 1e-12`, ~4500x the real noise floor,
~1e4x smaller than the smallest policy threshold) applied consistently to all five
threshold comparisons in the function. Independent critic: ACCEPT-WITH-CAVEATS
(flagged and we then tightened EPS from an initial 1e-9 to 1e-12 per its own
calculation). 0 regressions, 143→144 flywheel tests, non-vacuous before/after proof.

## MetaHarness Current Capability

`@metaharness/flywheel` has three independent evidence layers: (1) the promotion gate
(`meetsPromotionRule`, anchor suite, anytime-valid sequential evidence), (2) Ed25519-signed
replay-verified lineage (`verifyReplayBundle`), and (3), as of 4 days ago,
`verifyMultiGenerationEvidence` — a new primitive that classifies evidence into
`STRUCTURAL_MULTI_GENERATION` / `SYNTHETIC_RECURSIVE_IMPROVER` / `BOUNDED_RECURSIVE_IMPROVER`
/ `INDEPENDENT_CONFIRMATION`, explicitly disclaiming any RSI (recursive self-improvement)
claim (ADR-318). No dream-cycle night had reviewed layer 3 before tonight.

separating "child got better" / "improver got better at improving" / "externally
confirmed", plus Ed25519-signed lineage. RRSI's OOD-generalization regularization is a
real capability this repo's static anchor suite doesn't have — a legitimate future gap,
not tonight's fix.

## Hypothesis

Given a `GenerationEvidence` whose improver-yield delta (or primary delta, relative-cost-
reduction, or control-primary-margin) is mathematically exactly at a
`DEFAULT_MULTIGEN_POLICY` threshold, when `verifyMultiGenerationEvidence` evaluates it,
then the verdict must be identical regardless of which integer (wins, attempts) pair
produced the mathematically-equal delta — subject to: (a) existing passing/failing cases
unaffected, (b) the epsilon tolerance stays far smaller than any policy threshold so it
cannot mask a real shortfall, (c) 0 regressions in the existing suite.

## Recommended Next Steps

1. **Tighten or re-justify `THRESHOLD_EPS`** if a future caller feeds non-ratio
   `Outcome` fields with tighter real-world precision requirements than 1e-12 — flagged,
   not acted on, by tonight's independent critic.
2. **RRSI-style OOD/generalization regularization** is a real, published, directly
   comparable capability (arXiv:2609.24972) this repo's static anchor-suite design lacks
   — a legitimate candidate for a future `flywheel-promotion` or `darwin-evolution` night,
   not attempted tonight (would be a design-level ADR discussion, not a small patch).
3. **Confirmation-set digests are never bound to content** (ADR-318 half-discloses this:
   "does not prove semantic non-overlap") — a content-preserving reorder of a confirmation
   set changes its hash while leaving the evaluated items identical. Real, but a genuine
   content-commitment fix is a larger design change than tonight's scope; good candidate
   for a dedicated `security-adversarial` night.
