## INFERENCE

A fabricated-but-schema-valid SPDX checksum (the pre-#445 state) is plausibly
*worse* than an honest omission: it passes automated shape validation while
conveying false provenance confidence to a downstream auditor — this repo's
own ADR-250 "looks compliant, isn't" pattern, here applied to the SBOM
tooling itself. The fact that tonight's *fresh, independent* research path
re-derived the identical root cause and essentially the identical fix
construction (`sriToSpdxChecksum`: SRI string → base64 decode → hex,
strongest-algorithm-wins, never fabricate) is evidence the original fix is
well-targeted, not just plausible-sounding.

The recurrence itself (this is documented as the *third* independent
rediscovery of this bug-class on this exact surface, per PR #431's own body
citing #400 from 2026-10-13) is evidence that the zero-merge backlog is not
merely "slow human review of settled work" — it is actively costing
compounding re-derivation effort across nights, which previous nights'
framing (e.g. 2026-08-27's #239/#240) under-stated.
