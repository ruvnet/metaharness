## OBSERVATION

- `packages/flywheel/src/receipts.ts`'s `canon()` (deterministic sorted-key JSON canonicalization —
  the exact bytes every Ed25519 receipt signs/verifies) recursed with no depth bound. It is the single
  choke point `receipts.ts` (sign/verify), `replay.ts` (`sealedFieldsAuthentic`), and
  `multigeneration-proof.ts` (`validAttestation`, prior-child binding, the final evidence digest) all
  canonicalize through.
- Confirmed by direct code reading: `replay.ts:226`'s `sealedFieldsAuthentic` check and
  `multigeneration-proof.ts`'s `validAttestation()` (line ~239) and prior-child binding (lines ~321-322)
  call `canon()` on an UNTRUSTED `receipt.payload` (or `GenerationEvidence` field) with no prior
  shape/depth validation and no surrounding try/catch. `validate-bundle.ts`'s `validateReceipt` only
  checks `isPlainObject(r.payload)` — it never inspects the payload's internal depth.
- Confirmed exploitable, not merely theoretical: `validOutcome()`/`validProbe()`
  (`multigeneration-proof.ts`) check only the 4-5 NAMED fields of an `Outcome`/`ImproverProbe` are valid
  numbers; they never reject an object for carrying EXTRA keys. `coreGeneration()` spreads the whole
  `GenerationEvidence` (minus `reviewerAttestations`) into the unconditional final
  `evidenceDigest: multiGenerationEvidenceDigest(e)` computation at the end of
  `verifyMultiGenerationEvidence` — so a deeply-nested extra key on `g.child`/`g.baseline` sails past
  every named-field check and still reaches `canon()`, unconditionally, on every single call.

  accumulate `failures: string[]` and return a structured verdict in every other branch) — to NEVER
  throw. An uncaught native `RangeError` from unbounded recursion violates that contract.

## INFERENCE

- The bug class ("a bound exists on one axis — numeric magnitude in `validate-bundle.ts` — but not
  another — recursion depth in the shared `canon()` primitive") is the same shape the Deep Researcher's
  and Competitor Analyst's external research independently converged on as 2026's dominant agent-tooling
  DoS pattern, from two unrelated angles (CVE record; async-vs-sync-parser-bound-mismatch literature).
  That convergence is evidence the fix targets a real, currently-relevant class of gap, not a
  theoretical/academic one.
- The unconditional reachability of `multiGenerationEvidenceDigest(e)` at the very end of
  `verifyMultiGenerationEvidence` — regardless of whether any other check already failed — makes this
  the single highest-leverage call site: it is hit on every call, not just a specific comparison branch,
  so bounding `canon()` and fail-closing this one site closes the most severe instance of the gap by
  construction.
- Framing honesty check (ADR-250): the fix does NOT make the CLI path crash the whole process — `create-
  agent-harness/src/bin.ts`'s existing top-level `.catch()` already converts any thrown `Error` into a
  clean one-line message and `process.exitCode = 1`. The real, precise defect this candidate closes is
  narrower but still real: (a) pre-fix, that one-line message was an opaque, engine-specific
  `RangeError` whose trip depth varies with available stack space, not a deterministic rejection; (b) the
  14 programmatic/library callers outside the CLI wrapper (see OBSERVATION) had no such protection at
  all — an uncaught `RangeError` there is a genuine crash of the calling script, not a clean exit.

## HYPOTHESIS (frozen before implementation)

Given a `ReplayBundle` or `MultiGenerationEvidence` containing a `receipt.payload` (or an evidence field
carrying an extra, unvalidated key) nested deep enough to exhaust the native call stack, when `canon()`'s
recursion depth is bounded to `MAX_CANON_DEPTH = 64` (failing closed with a clear, deterministic `Error`
rather than relying on the engine's native stack limit) and every verification call site that compares
an untrusted value (`replay.ts`'s `sealedFieldsAuthentic`, `multigeneration-proof.ts`'s
`validAttestation` and prior-child binding, and the unconditional `evidenceDigest` computation) swallows
that error into a fail-closed verdict rather than letting it propagate, then `verifyReplayBundle()` and
`verifyMultiGenerationEvidence()` continue to honor their documented contract of always returning a
structured verdict — subject to: (a) byte-identical `canon()` output for every value under the depth
bound (no behavior change to the canonicalization algorithm itself); (b) 0 regressions on all 7 real
committed `ReplayBundle` artifacts in this repo; (c) `MAX_CANON_DEPTH=64` stays well above any real
payload's actual nesting (verified: every real committed receipt payload in this repo is flat or
one-level nested). Not modified after evaluation began.

## DECISION

reasoning) returned **ACCEPT** with 2 non-blocking caveats, both independently verified by the critic
