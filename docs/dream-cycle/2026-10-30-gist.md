# Generator-Genome SOTA Report — 2026-10-30

TL;DR: `harness genome`'s `scorePublishReadiness()` credited a `+0.15` "can test"
bonus for ANY language-inferred `testCommands` entry (e.g. any repo with a bare
`pyproject.toml` gets `pytest` pushed automatically) with zero check that real
test files exist. `publish_readiness` carries the single largest weight (0.5)
in `genome.ts`'s `risk_score` and directly gates the `ready`/`needs-work`/
`blocked` verdict + process exit code — so a zero-test Python repo (manifest +
build command + CI, no test files) scored `publish_readiness: 0.90`,
`risk_score: 0.275`, verdict **ready**, exit 0. Fixed by gating the credit on
the same real-filesystem evidence (`hasVerifiedTestFiles`) three sibling
scorers in this file/package already require; the identical fixture now scores
`0.75`/`0.35`, verdict **needs-work**, exit 1 — a real, live-CLI-reproduced
verdict flip, not a synthetic unit-test number.

## MetaHarness Current Capability

`genome-scorers.ts` is the pure-scorer module behind `harness genome`'s 6-field
scorecard. Three of its five dimensions already require real filesystem
evidence that test files exist (`hasVerifiedTestFiles`, populated by
`analyze-repo.ts` from a `tests/`/`__tests__`/`test` directory scan) rather
than trusting manifest-inferred `testCommands` alone — `scoreTestConfidence`
(fixed 2026-08-25, #229), plus `score.ts`'s `scoreTestCoverage` and
`repo-scorecard.ts`'s `compileConfidence` (both fixed, still on unmerged
branches). `scorePublishReadiness` was the one holdout, and the
highest-stakes: it alone feeds the dominant term of `risk_score` and the
process exit code a CI pipeline or human would actually act on.

fix closes the one place that edge was still only half-true.

## Hypothesis

Given a repository profile where `testCommands` is populated by
language/manifest detection alone (e.g. a `pyproject.toml`-only Python repo)
with zero real test files on disk (`hasVerifiedTestFiles === false`), when
`scorePublishReadiness()` is applied, then the `+0.15` "can test" credit
should be withheld — matching the behavior already established in three
sibling scorers — subject to: an authored `npm test` script (the one
`testCommands` entry that is NOT language-inferred) still counts as real
evidence; repos with verified test files or an authored `npm test` script see
byte-identical scores; `genome.ts`'s verdict-threshold logic itself is
unchanged (only the input signal is corrected).
