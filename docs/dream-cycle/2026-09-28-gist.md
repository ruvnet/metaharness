# Security-Adversarial SOTA Report — 2026-09-28

TL;DR: The `--max-cost` hard spend cap on `bench/swebench/solve-*.mjs`'s live-spend
scripts silently disabled itself on malformed input (`NaN >= x` is always `false`),
exactly the finding last night's Dream Cycle (#359) disclosed but deferred as "more
severe than tonight's fixes — unlimited real spend." Closed with a small, tested,
fail-closed helper, across 10 files after two rounds of independent critique each
found real gaps. **Round 2's own "be thorough" pass then found 8 MORE live,
unpatched instances of the identical fail-open pattern** elsewhere in
`packages/darwin-mode/bench/` — including a process-killing watchdog whose
runaway-kill comparison can be silently defeated the same way — not fixed tonight,
disclosed as the most severe open finding. Separately: 29 of 31 real test files
under `packages/darwin-mode/bench/swebench/` are silently unreached by any CI
runner, and the repo's own purpose-built `check-runner-coverage.mjs` gate (built for
exactly this failure mode, per issue #194) has a blind spot that hides them from its
own report.

## MetaHarness Current Capability
5 scripts in `packages/darwin-mode/bench/swebench/` make live, real-money OpenRouter
calls to run SWE-bench solver loops: `solve-advisor.mjs`, `solve-agentic.mjs`,
`solve-fusion.mjs`, `solve-mcts.mjs`, `solve-repair.mjs`. Each takes a `--max-cost`
flag as its **hard** budget cap — the only in-process guard against runaway spend.
`solve-repair.mjs`'s own comment records why it exists: "lesson from the 2026-06-22
overage: an out-of-process watchdog can be killed and miss the threshold." All 5
parsed it identically: `const MAX_COST = +argv('--max-cost', Infinity);` then
`if (totalCost >= MAX_COST) { …stop… }`.

The "None" rows above are a real, if unsurprising, gap: none of the 3 major
open-source multi-agent frameworks publish anything at the level of "how do we
validate a numeric spend-cap CLI flag" — this is exactly the kind of small,
un-glamorous input-validation detail that doesn't get a blog post, doesn't block a
release, and only surfaces after an incident (as it did here). That is the same
pattern OWASP's 2026 re-ranking is responding to: not a novel attack technique, just
an increasingly load-bearing failure mode as more of these scripts run unattended
and spend real money.

## Hypothesis
Given a live SWE-bench solver invocation launched with a malformed `--max-cost`
value (non-numeric text, coercing to `NaN`), when the hard-cap parsing is replaced
with `numericFlag()` (throws before any LLM call), then the script refuses to start
instead of running with an effectively unlimited budget — subject to: byte-identical
behavior for every currently-valid `--max-cost` value (including the explicit
`Infinity` sentinel), zero behavior change to any other flag, 0 regressions in the
darwin-mode suite.

## Evaluation
- **Baseline (pre-fix, reproduced empirically)**: `+"abc"` → `NaN`; `999 >= NaN` →
  `false`. Confirmed via direct `node -e` repro before writing the fix.
- **Candidate (round 1)**: `packages/darwin-mode/bench/swebench/lib/numeric-flags.mjs`
  (`numericFlag`) wired into all 5 solver scripts' `MAX_COST` line.
- **Independent critic, round 1: ACCEPT-WITH-CAVEATS.** Fix itself correct,
  minimal, non-regressive — but found 2 real gaps: (a) `argv('--max-cost', undefined)`
  returns `undefined` both when the flag is absent AND when it's the last token
  on the command line with no following value (a realistic shell-interpolation
  accident) — `raw === undefined` couldn't tell them apart, so the dangling-flag
  case silently fell back to `Infinity`, **reopening the exact bypass**; (b) the
  identical pattern was unpatched in `solve-avo.mjs` (`--budget-usd`),
  `bench/cve-bench/solve-cve.mjs`, `bench/gaia/solve-gaia.mjs` (all literally
  `+argv('--max-cost', Infinity)`), and `evolve-config.mjs`/`evolve-perinstance.mjs`'s
  `costCap` (real VM-provisioning spend, same `s - startSpend > costCap` NaN-bypass
  shape) — a materially larger blast radius than the 5 originally-cited files.
- **Candidate (round 2)**: `numericFlag` now calls `argv(flag, ABSENT)` with a
  module-local `Symbol()` sentinel instead of `undefined`, so "absent" and
  "present-but-dangling" are distinguishable — the latter now throws instead of
  defaulting to unlimited. Wired into the 5 additional sites the critic found.
  9 `node:test` unit tests (added: dangling-flag-throws).
- **Independent critic, round 2: ACCEPT-WITH-CAVEATS.** Confirmed the
  `ABSENT`-sentinel fix is correct (module-private `Symbol()`, cannot collide,
  cannot leak into `args[i+1]` since that slot only ever holds real CLI
  strings) and re-derived the 5 additional sites are wired correctly with no
  behavior change (`solve-avo.mjs`'s `BUDGET_USD` default `'30'`→`30`: only
  consumer is a numeric comparison plus one template-literal log line, both
  identical for `30` vs `'30'`). **But**: a deliberately broader "be thorough"
  second-pass search for the same `+argv(...)`/`Number(argv(...))` → hard-cap
  `>=`/`>`/`<=`/`<` shape turned up **8 more live, unpatched instances**
  outside tonight's fixed set — see Recommended Next Steps §1, now promoted to
  the top finding.
- **Full darwin-mode suite**: 74 files / 665 tests passed, 14 pre-existing skips,
  **0 regressions** (identical pass/skip count to the 09-27 baseline). Ran 3×;
  one run had a bare nonzero `npm` exit despite vitest's own summary reporting
  all-green, did not reproduce on 2 subsequent clean runs — treated as a
  pre-existing environmental flake (real child-process-spawning e2e tests in
  this suite), not caused by this diff; disclosed, not chased further.
- **tsc --noEmit**: clean.
- **`scripts/check-runner-coverage.mjs`**: still exits 0 (the new test is now
  explicitly wired into `ci.yml`, so it doesn't add to the coverage gap below).
- receipt: `EVALUATED=yes, VERDICT=ACCEPT`. Both independent critic rounds
  returned ACCEPT-WITH-CAVEATS on the specific diff reviewed at that round
  (never REJECT); every gap either round found within tonight's own claimed
  scope was fixed and re-verified same night. The caveats that remain
  (8 more files, the CONCURRENCY sibling idiom) are explicitly *out* of
  tonight's frozen hypothesis's scope, not open issues within it — hence
  ACCEPT rather than ACCEPT-WITH-CAVEATS for tonight's own candidate, with
  the caveats carried forward as Recommended Next Steps instead.

## Recommended Next Steps
1. **(most severe, disclosed not fixed)** The identical fail-open NaN-bypass
   pattern (`+argv(...)`/`Number(argv(...))` feeding a hard-cap `>=`/`>`/`<=`/`<`
   comparison) is live in at least **8 more files**, found by round 2's
   independent critic doing a deliberately broader sweep after round 1's fix
   turned out to be narrower than its own doc comment claimed:
   `bench/cognition/run-cognition.mjs` (`MAX_COST`, `ABORT_USAGE`),
   `bench/gaia/solve-gaia.mjs`'s own sibling `ABORT_USAGE` flag (its `MAX_COST`
   *was* fixed tonight — `ABORT_USAGE` in the same file was not),
   `bench/livecodebench/solve-lcb.mjs` (`MAX_COST`),
   `bench/ruvector/h3-pilot.mjs` and `h1-pilot.mjs` (`MAX_COST`, `ABORT_USAGE`),
   `bench/orchestration/probe.mjs` (`ABORT_USAGE`),
   `bench/ruvector/ruvector-eval.mjs` (`MAX_COST`, `ABORT_USAGE`), and —
   **most severe of all** — `bench/swerebench/budget-watchdog.mjs`'s `CEILING`,
   which drives a **SIGTERM kill-switch on a runaway process**: a malformed
   `CEILING` input means the one out-of-process safety net for exactly the
   "watchdog can be killed and miss the threshold" scenario `solve-repair.mjs`'s
   own comment warns about never fires at all. (Critic also checked
   `gepa/run-gepa.mjs`/`gepa/overnight-train.mjs`'s `<`/`<=` comparisons — those
   fail *closed* on NaN, not open, so not part of this list.) Two rounds of
   independent critique in one night, each surfacing a real gap the fix's own
   author (this session) missed — a strong argument for a dedicated future
   `security-adversarial` night doing one exhaustive `bench/**` sweep with
   `numericFlag` rather than another piecemeal per-file pass; tonight
   deliberately stopped expanding scope after 2 rounds rather than chase a 3rd.
2. `scripts/check-runner-coverage.mjs` —
   purpose-built (issue #194) to catch "a test file is never run but CI reports
   green" — has a blind spot: it only checks whether the *owning package* has
   any `test` script, not whether that script's actual include glob reaches the
   specific file. Root vitest.config.ts's `include` is
   `packages/*/__tests__/**/*.test.ts` — it never matches anything under
   `bench/swebench/`, and never matches `.mjs`. Result: **29 of 31** real,
   `node:test`-based test files under `packages/darwin-mode/bench/swebench/`
   (advisor-loop, fusion-loop, evolve-arch, evolve-config ×3,
   evolve-perinstance, localize, reviewer, repro-gate, policy-seam,
   capability-lever, output-modes, handoff, trace-localize,
   swebench-grade-venv, endpoint-auth, freeze-swebench-suites,
   flywheel-swebench-evaluator, swebench-solver-cli, agentic-loop-native, and 8
   `gepa/*.test.mjs` files) are **not executed by any CI runner**, and the
   coverage gate itself reports 0 of them as unreached (56 unrelated
   root-level/`services/`/`kimi-k3-harness` files are correctly flagged and
   allowlisted — none from `bench/swebench/`). Spot-checked 5 of the 29
   (advisor-loop, fusion-loop, evolve-arch, localize, reviewer — 57 tests
   total): all currently pass, so this is a structural/verification-integrity
   gap, not evidence of an active undetected regression. Good candidate for a
   dedicated near-future `security-adversarial` or `flywheel-promotion` night:
   fix requires a real glob matcher against `vitest.config.ts`'s `include`
   array (checker is deliberately zero-dependency) plus allowlisting the 29
   newly-surfaced files with individual reasons, per the allowlist's own
   documented "ratchet" contract.
3. The sibling `CONCURRENCY = Math.max(1, +argv('--concurrency', 1))` idiom
   (present in several of these same files) has a different, lower-severity
   failure mode on malformed input: `Math.max(1, NaN)` is itself `NaN`
   (verified via `node -e`), which reaches `Array.from({ length:
   Math.min(CONCURRENCY, manifest.length) }, …)` — `Array.from` clamps a `NaN`
   length to `0`, so the worker pool silently starts zero workers and the
   script does nothing (fails silent-no-op, not silent-runaway-spend). Real,
   but a different bug class from a financial-safety-gate defeat; flagged, not
   fixed tonight — `numericFlag`'s `ABSENT`-sentinel design generalizes to
   this case too, so wiring it in is a mechanical follow-up, not a redesign.
4. `packages/create-agent-harness/src/learn.ts`'s `--max-cost` (line ~110) is a
   pure string passthrough to a child solver invocation — it now inherits
   tonight's fix transitively wherever it shells out to one of the patched
   scripts, but this wasn't independently verified end-to-end tonight (no live
   spend was used to confirm it). Worth a `--dry-run`-only confirmation on a
   future `learn`-focused night.
