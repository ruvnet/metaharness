# generator-genome SOTA Report — 2026-08-25

**TL;DR**: MetaHarness's `harness genome` test-confidence scorer trusted a
repo's *manifest* (a `pyproject.toml`/`go.mod` existing) as proof tests
exist — a repo with a `"test": "echo no tests"` script and CI wired, but
zero real test files, scored 0.8/1.0 `test_confidence`. 2026 research on
agentic-coding harnesses confirms this "manifest implies tests" shortcut
is a known, actively-measured failure mode (arXiv:2606.18168: 80.2% of 86k
agent-authored test patches had weak-or-no assertions; arXiv:2607.18057:
64.8% of Python agentic PRs execute zero test-covering-changed-lines), and
a free OSS competitor (kodustech/agent-readiness) already does the
real-file-glob check MetaHarness's own sibling scorer (`score.ts`) only
partially does. Fixed: `scoreTestConfidence` now requires real filesystem
evidence (`hasVerifiedTestFiles`, a directory scan) for its base credit,
closing a gap disclosed as open in 2026-08-15's #200 gist. The
adversarial critic found and closed a real coverage gap (the fs-scan path
had zero real-filesystem test exercise) before this candidate shipped.

## MetaHarness Current Capability

`genome-scorers.ts`'s `scoreTestConfidence(profile)` credited
`profile.testCommands.length > 0` (+0.5) and `profile.hasCi` (+0.3)
directly. `testCommands` is built in `analyze-repo.ts` purely from
language/manifest detection — `pyproject.toml`/`requirements.txt` present
→ `'pytest'` pushed unconditionally, `go.mod` present → `'go test ./...'`
pushed unconditionally, `package.json`'s `scripts.test` key existing →
`'npm test'` pushed — none of it checks whether any test *file* exists.
Meanwhile this package's own sibling `score.ts::scoreTestCoverage` already
does a real `dirExists(dir, '__tests__'|'tests'|'test')` filesystem scan
for its largest score component. This is the third instance of a
"measures the proxy, not the real repo state" bug class found in this
exact package: 2026-08-14's #196/#171 fixed an analogous `taskCoverage`
bug, 2026-08-15's #200 fixed `scorePublishReadiness`'s language allow-list
and explicitly flagged this scoreTestConfidence gap as an open next-step.

Both this gap and the 08-15 fix remain **unmerged on `main`** — see the
operational finding below.

## Hypothesis

Given `analyze-repo.ts`'s `testCommands` inference (language/manifest
presence only) and `genome-scorers.ts`'s `scoreTestConfidence(profile)`
(which credited `testCommands.length > 0` regardless of whether real test
files exist), when test-confidence is gated on real filesystem evidence —
`hasVerifiedTestFiles`, a `tests`/`__tests__`/`test` directory scan added
to `inventory()`, mirroring `score.ts`'s existing `dirExists` pattern —
then a repo with a test-capable manifest/CI but zero real test files
should score materially lower `test_confidence` (and higher `risk_score`,
since `risk = 0.5*(1-publish) + 0.3*mcp + 0.2*(1-testConf)`) than an
equivalent repo with real test files present, subject to: (a) existing
behavior for repos that DO have real tests is unchanged or improves, (b)
`score.ts`'s already-correct `scoreTestCoverage` is not regressed, (c) no
existing test weakened, (d) diff stays materially under 300 lines, (e)
zero LLM/model calls required.

## Adversarial Critique

Independent critic (fresh subagent, no authorship context) reached
**ACCEPT-WITH-CAVEATS**, verifying rather than trusting the self-report:
re-ran `tsc`+`vitest` itself (464/464 match), re-derived the pre-fix
stash-and-rerun counterfactual itself (4/6 fail, matched), grepped all
`RepoProfile` construction sites repo-wide and confirmed `apps/web-ui` and
`darwin-mode` each declare independent, non-importing `RepoProfile`
interfaces (new optional field can't break them), and confirmed the
`'__test_dir__'` marker key can't collide with a real scanned file (never
populated from `HIGH_SIGNAL` or the raw `readdirSync` loop). Found two
caveats, both closed pre-ship: (1) the new fs-scan path in `inventory()`
had zero coverage against a **real** filesystem — closed with 2 new
`mkdtemp`-based tests; (2) a docstring overclaim that `score.ts` "already
requires" real directory evidence, when it only weights it as the largest
of three independent components — softened to the actual, narrower parity.

## Recommended Next Steps

1. **Glob real test *files* per language, not just a directory.** A repo
   with an empty `tests/` directory (or one containing only fixtures, no
   assertions) still passes tonight's `hasVerifiedTestFiles` check — the
   directory-only signal is a real improvement over pure manifest
   inference but is not yet at kodustech/agent-readiness's tier (per-file
   glob + declared test-framework-dependency check). Natural next-night
   candidate for this exact surface.
2. **Operational finding, arguably more important than tonight's fix**:
   **6 consecutive Dream Cycle PRs spanning 2026-08-15 through 2026-08-24
   (11 calendar days) are still open/draft/unmerged** (#200, #205, #207,
   #210, #212, #224) — including two adversarially-critiqued real
   security/RCE fixes (#210, #224) and tonight's own direct predecessor
   (#200), all `mergeable_state: clean`. This zero-merge-rate is exactly
   the STEP 1.1 signal this pipeline exists to react to — reflected
   tonight in picking the smallest, most surgical candidate available over
   the larger `mcp:'off'` finding below. This is a human-review bottleneck,
   not a research-quality one.
3. **`mcp:'off'` is structurally unreachable through `recommendPlan()`,
   contradicting ADR-022's explicit intent** ("`off` is a first-class
   mode... a memory-only or CLI-only harness is valid"). Every
   `analyze-repo.ts` archetype sets `mcp: 'local'` or `'remote'` — none
   `'off'` — so `scoreMcpRisk`'s zero-risk branch is dead code even when
   `hasMcp: false`. Confirmed via git history + ADR-022 cross-check.
   Scored lower than tonight's pick on reviewability (larger blast
   radius) under STEP 1.1's zero-merge bias, but is the stronger
   architectural finding — a good candidate once the review backlog
   clears.
