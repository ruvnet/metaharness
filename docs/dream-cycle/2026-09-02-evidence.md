# Dream Cycle 2026-09-02 — Flywheel Evidence Record

Durable evidence for tonight's darwin-evolution candidate, classified per the Dream Cycle
knowledge-type discipline.

## OBSERVATION

Three independent research passes tonight (Deep Researcher, Architecture Reviewer, and the
Competitor Analyst's field survey of verifier-honesty risk in self-modifying harnesses)
converged, unprompted, on the same finding: `packages/darwin-mode/src/tier2-sandbox.ts` (the
`'agent'` / Tier-2 sandbox, ADR-106) never calls `inspectVariant` (the ADR-071 safety gate)
before `tier2-driver.ts` `import()`s and executes a variant's real, generated TypeScript surface
files in a child process. The module's own doc comment claimed "The gate (`inspectVariant`) has
already cleared the variant before any execution" — false. This exact gap was already found and
explicitly left open in yesterday's `docs/adrs/ADR-273-darwin-llm-agent-sandbox.md` ("`inspectVariant`
is in fact never called anywhere on the Tier-2 code path today — confirmed by search. Out of scope
to fix here"). The two sibling sandboxes, `sandbox.ts` (`real`) and `llm-agent-sandbox.ts`
(`llm-agent`, ADR-273's own new code), both correctly gate first.

## MEASUREMENT

- **Non-vacuous baseline proof (real code execution, not just a metadata mismatch)**: constructed
  an adversarial variant directory — six approved surface files copied unmodified from a real
  generated baseline, one (`context_builder.ts`) poisoned with a top-level `import { writeFileSync }
  from 'node:fs'` plus a call writing a marker file. `inspectVariant(dir)` correctly flags it
  directly (control). On unpatched `tier2-sandbox.ts`, calling `runVariantTaskAgent`/
  `runVariantTasksAgent` returned `exitCode: 1` (never gated) **and the marker file was created**
  (`existsSync === true`) — the malicious module's code genuinely executed inside the child
  process, with real Node capabilities, before any scoring happened.
- **Fix**: `runVariantTaskAgent` now calls `inspectVariant(variant.dir)` first and returns a
  `exitCode: 99` disqualified `RunTrace` (mirroring `sandbox.ts`/`llm-agent-sandbox.ts`'s existing
  convention) when findings are non-empty, before `execFile` ever spawns `tier2-driver.js`.
- **Non-vacuous fix proof**: re-ran the identical adversarial fixture against the patched code —
  `exitCode: 99`, non-empty `blockedActions`, and the marker file is **never created**, across both
  `runVariantTaskAgent` (single task) and `runVariantTasksAgent` (every task in the default suite,
  not just the first).
- **Control (no regression)**: a clean, unmodified generated baseline variant is unaffected —
  `inspectVariant` returns `[]`, and none of its task traces carry `exitCode: 99`.
- **Full regression check**: `npx vitest run` (darwin-mode) → 74 test files, **657 passed / 14
  pre-existing skips**, 0 failures — identical pass count to pre-fix outside the 2 new tests. Full
  monorepo `npm run build` (4 phases): clean.
- **Independent adversarial critic** (fresh sub-agent, no authorship context): verdict **ACCEPT**.
  Traced every call path into `tier2-driver.js` and confirmed no bypass exists (`runVariantTasksAgent`
  only calls the now-gated `runVariantTaskAgent`; `evolve.ts` only calls `runVariantTasksAgent`;
  `tier2-driver` is referenced nowhere else in `src/`). Confirmed `scorer.ts`/`evolve.ts` handle the
  new `exitCode: 99` traces generically (no sandbox-mode special-casing), so this doesn't silently
  break score/promotion logic. Confirmed `git diff --stat` scope is exactly the source fix + the one
  new test file (no existing test weakened, no threshold touched, dist matches a fresh rebuild). One
  cosmetic nit (a test comment referencing `require(` instead of the actual `node:fs` import
  mechanism used) — fixed.

## INFERENCE

The fix closes a real, previously-disclosed-but-unfixed invariant violation without changing
behavior for any variant that already passes the gate: the change is a pure prepend (an early
return on non-empty findings) to the one function every Tier-2 evaluation path funnels through,
and the regression suite proves it byte-identical on the happy path. The non-vacuous before/after
proof (a real side-effect marker file, not just an exit code) rules out the fix being a metadata-only
patch that leaves actual code execution unguarded through some other path.
