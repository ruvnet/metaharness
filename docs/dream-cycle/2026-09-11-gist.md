# The Flywheel's Frozen Gate Had a Ceiling Lockout — 2026

TL;DR: `@metaharness/flywheel`'s default `meetsPromotionRule` gate requires
a candidate's no-op rate to *strictly* improve on the baseline, with no
floor case. Once a lineage's baseline no-op rate hits 0 (a policy that
never fails to commit), that clause becomes permanently unsatisfiable —
no future candidate can ever promote again on that branch, no matter how
much better it is on every other axis. This isn't hypothetical: the
repo's own flagship mechanism-proof artifact, `experiments/signal-flywheel`,
hit this exact wall at generation 2 of 8 and silently discarded a
genuinely-better candidate (primary +5.95%, cost -8.34%) six generations
running. Fixed with a 3-line, independently-critiqued patch that only
relaxes the clause when the baseline is already unbeatable.

## MetaHarness Current Capability (before tonight)

`packages/flywheel/src/gate.ts`'s `meetsPromotionRule` is the frozen,
fingerprintable, Ed25519-lineage-signed default promotion gate — "the
gate is the product," per its own header comment. Clause 2:
`candidate.noopRate < baseline.noopRate` (strict), unconditional. `Score`
documents `noopRate` as a floor-0 fraction. No test in
`packages/flywheel/__tests__/` exercised `baseline.noopRate === 0`, and no
ADR (234/235/274) discusses this edge case — an undocumented oversight,
not an intended tradeoff.

## Hypothesis

Given a flywheel lineage whose baseline `Score.noopRate` is already at
its floor (0), when a candidate `Score` ties that floor while strictly
improving `primary` and not worsening `costPerWin`/anchor/safety, then
`meetsPromotionRule` should PROMOTE — where today it REJECTS solely via
`noop_rate_not_improved` — subject to: (a) any `baseline.noopRate > 0`
case must still require strict improvement, unchanged; (b) no other
clause's semantics change; (c) zero regressions in the existing flywheel
suite; (d) the real, already-committed `experiments/signal-flywheel`
rejections (gen 4/6/8, `retryLimit`, primary 0.950695) must re-evaluate as
promotable under the patched gate. Frozen before implementation.
