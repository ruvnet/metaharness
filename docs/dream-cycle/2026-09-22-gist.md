# Darwin-Evolution SOTA Report — 2026-09-22

TL;DR: Tonight's darwin-evolution candidate is a small scorer-wiring fix: `@metaharness/darwin`'s ADR-249
`traceQuality` seam (weight 0.15 in the six-term weighted score) was defined and unit-tested, but — like the
`cost` half of the same seam before 2026-08-17, and the Tier-2 ADR-071 safety gate before 2026-09-02 — was

## MetaHarness Current Capability

`@metaharness/darwin`'s `evolve()` loop (profile → mutate → sandbox → score → archive → select) scores every
variant on 6 weighted terms (taskSuccess .35, testPassRate .20, traceQuality .15, costEfficiency .10,
latencyEfficiency .10, safetyScore .10) minus a hard penalty layer, gated by 4 promotion clauses (ADR-072).
Two of six terms have opt-in ADR-249 seam upgrades over their pre-seam heuristics: `cost` (wired 08-17) and
`traceQuality` (wired tonight). All 3 sandbox tiers now call the ADR-071 safety gate first (fixed 09-02, #272
— still unmerged).

## Hypothesis

Given `evaluateVariant()`, which already wires `costBudgetBytes` into `scoreVariant`'s opt-in `signals.cost`
(ADR-249) but never populates the sibling `signals.traceQuality` seam — so that 0.15-weight term is a provable
constant 0.9 in default `'real'` mode — when a new opt-in `traceQualityFromOutput` boolean is added and, when
true, `evaluateVariant` feeds the fraction of a variant's traces with non-empty stdout+stderr through
`signals.traceQuality`, then the term should discriminate between variants whose traces differ in
emptiness/degeneracy, subject to: (a) omitting the option keeps scoring byte-identical, (b) zero existing test
regresses, (c) the signal stays orthogonal to `safetyScore`/`toolLoop` so it never double-penalizes the same
trace property under a different name.

## Adversarial Critique

Independent fresh-subagent critic, cold-read: re-ran both test commands itself (not taken on faith),
independently reproduced the non-vacuous baseline failures and the post-fix 16/16 + 665/665 pass, restored the
tree to the fixed state, and verified via `git diff --stat`. Confirmed zero weakened assertions, orthogonality
vs. `safetyScore`/`toolLoop`, and the byte-identical-when-omitted claim (by inspection + stashed-baseline run).

**Disclosed gap (real, not a blocker):** `substantiveTraceRatio` treats ANY non-empty output — even one
whitespace byte — as "substantive." Opted in, a mutated variant could unconditionally emit one junk byte per
task and max `traceQuality` at 1.0, clearing `promotionDelta` (0.02) on an otherwise-neutral mutation — a
materially larger gaming surface than the pre-seam constant-0.9 (which nobody could move). Opt-in and off by
default — zero risk in the default `'real'` mode — and untested here. **Verdict: ACCEPT-WITH-CAVEATS.**
Hardening is a disclosed next-night finding (Recommended Next Steps).
