# generator-genome SOTA Report — 2026-11-05

TL;DR: `analyzeFiles()`'s `hasCi` detector matched the bare word "workflow" anywhere in a
repo's README/manifest text — a repo that merely describes its own *development* workflow,
with zero `.github/workflows` directory and zero verified test files, was read as CI-equipped.
That false signal feeds `resolveAgentTopology()`, silently granting a `tester`/`release` agent
recommendation the repo never earned — bypassing three prior hardening nights
(2026-08-25 #229, 2026-09-15 #314, 2026-10-25 #435) that closed the identical "manifest/text
trusted over real evidence" bug class for the sibling `hasVerifiedTestFiles` signal. Fixed by
requiring a named CI system or the literal workflows path, not the generic noun.

## MetaHarness Current Capability
`metaharness score`/`genome`/`analyze-repo` build a deterministic `RepoProfile` from a
fixed set of high-signal files (README, package.json, Cargo.toml, pyproject.toml,
CONTRIBUTING.md), then score it across archetype-fit, test-confidence, MCP-risk, and
publish-readiness dimensions — no LLM calls, no code execution, offline-reproducible.
14 nights of prior hardening have closed nearly every "trusted manifest/text over real
on-disk evidence" bug in this family (language allow-lists, `scoreTestConfidence`,
`resolveAgentTopology`'s tester gate, `toolSafety` constants, the `mcpRisk`-masks-grade
gap). Two still-open, previously-disclosed architecture notes remain live but out of
scope tonight: `recommendPlan()`'s `plan.policy` is a hardcoded `SAFE` constant (4/6
`constraints.ts` hard-gates are vacuously always-true); `analyzeFiles()`'s `hasMcp` only
checks `.mcp.json` + a loose regex, never `.claude/settings.json`'s real `mcpServers` (a
3rd unfixed sibling of the #276/#298 MCP-detection-consolidation bug class).

## Hypothesis
Given a repository whose prose files (README/package.json/Cargo.toml/pyproject.toml/
CONTRIBUTING.md) mention the generic word "workflow" with no real `.github/workflows`
directory, when `analyzeFiles()` computes `hasCi`, then `hasCi` should be `false` and
`resolveAgentTopology()` should not add `tester`/`release` on that basis alone — relative
to the baseline, which sets `hasCi: true` from the bare-word match; subject to: 0
regressions on repos with real CI (`.github/workflows/ci.yml` or a named CI system/path
in prose), no change to the already-fixed `hasVerifiedTestFiles`/tester-gate composition,
and the fix must stay a single-file, single-regex change given tonight's review-backlog
constraint (see below).
