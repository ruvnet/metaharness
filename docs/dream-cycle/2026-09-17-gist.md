# darwin-evolution SOTA Report — 2026-09-17

TL;DR: `metaharness learn`'s `--dry-run` — the ONE mode whose entire purpose is a $0
pre-spend sanity check — silently accepted a nonexistent `--slice`/`--manifest` file and

## MetaHarness Current Capability

`metaharness learn` (ADR-228) is a thin, repo-checkout-gated CLI wrapper that spawns
`packages/darwin-mode/bench/swebench/gepa/learn.mjs`. It validates `--seed` (existsSync,
already present) but never validated `--slice`/`--manifest` — and `learn.mjs`'s own
`--dry-run` branch returns before ever reading the manifest file, so the gap was invisible
in exactly the mode meant to catch it. A user could `learn --slice typo.json` (dry-run,
$0), see a plausible-looking printed plan, then `--run` and only discover the typo at the
first real candidate eval — no cost lost (the eval subprocess reads the manifest before any
LLM call), but the dry-run's implicit promise ("this is what would run") was false.

None of the agent-orchestration frameworks in the default comparison set ship a
GEPA-equivalent offline policy-evolution loop at all — this isn't a gap they're hiding, it's
a genuinely different design point (they optimize orchestration graphs, not a distilled
cheap-executor's operating policy). The interesting comparison is instead against
optimizer-shaped tools (DSPy, and non-agent infra tooling like Terraform) that share the
"cheap dry-run before an expensive real run" shape MetaHarness's `learn` command has — and
those already treat local input validation as a baseline dry-run responsibility.

## Hypothesis

Given a `metaharness learn` invocation whose `--slice`/`--manifest` does not resolve to an
existing file under the GEPA bench directory, when the command runs (dry-run or `--run`
alike), then it prints a clear, actionable error and exits non-zero BEFORE spawning
`learn.mjs` — where today `--dry-run` silently accepted it — subject to: valid slice values
(default and any real file) are unaffected; `--run` behavior for a valid slice is
byte-for-byte unchanged; the existing `--seed` validation pattern is reused, not reinvented;
0 regressions in `__tests__/learn.test.ts`. Frozen before implementation.
