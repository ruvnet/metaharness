# Darwin-Evolution SOTA Report — 2026-10-22

TL;DR: `darwin-mode`'s frozen promotion-gate scorer (ADR-072) only scanned a
variant's **stderr** for secret-leak/destructive-command/hallucinated-file
penalty patterns, never **stdout** — even though `sandbox.ts` captures both
as independent buffers from the same `execFile` call and the rest of the
codebase (`phenotype.ts`, `mutator.ts`) already treats them as one combined
channel. A variant whose test command happened to print a destructive
command or a leaked credential to stdout (the common default for most
Node/Jest/Vitest runners) scored as penalty-free. Closed with a 2-line,
2-stream scan; 0 regressions across darwin-mode's full 844-test suite; 4
new tests fail non-vacuously pre-fix.

## MetaHarness Current Capability
`scoreVariant()` (`packages/darwin-mode/src/scorer.ts`) is the single
authoritative promotion-gate scorer — "kernel code," immune to a variant's
own proposed weights (enforced by `scorer-immutability.test.ts`). Its
penalty layer runs three coarse regexes (`SECRET_RE`, `DESTRUCTIVE_RE`,
`HALLUCINATED_RE`) against trace output to zero out `finalScore` on a hit.
Before tonight it `.test()`'d only `t.stderr`; `t.stdout` — populated by the
identical `execFileAsync()` call in `sandbox.ts` — was invisible to all
three detectors.

## Hypothesis
Given a Darwin-mode variant's `RunTrace` (captured by `sandbox.ts`'s
`execFileAsync`, which returns `stdout`/`stderr` as independent buffers),
when `scoreVariant()`'s three penalty-layer detectors are extended to scan
`stdout` in addition to `stderr`, then detector recall on a pattern located
in stdout goes from 0% to 100% (matching existing stderr recall), subject
to: (a) all pre-existing stderr-only detections stay byte-identical (0
regressions on darwin-mode's 844 existing tests); (b) ADR-249's
byte-identical-absent-seam guarantee and ADR-072's 4-clause promotion gate
stay untouched; (c) the fix stays inside `scorer.ts`'s documented "pure
function, no I/O" contract.
