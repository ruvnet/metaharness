## HYPOTHESIS

Given a target repository with a test-capable manifest but zero real test
files on disk, when `metaharness score <repo>` computes `compileConfidence`,
then the test-signal term should require real evidence
(`hasVerifiedTestFiles` or an authored `npm test` script) rather than crediting
inferred `testCommands` directly — subject to (a) a repo with real verified
tests or an authored `npm test` script is unaffected; (b) `taskCoverage`'s
separate `testCommands.length` term is untouched (different dimension,
different semantics); (c) 0 regressions elsewhere. Frozen before
implementation in the gist; not modified after evaluation began. Confirmed
by the MEASUREMENT section above.
