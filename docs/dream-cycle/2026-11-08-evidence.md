## OBSERVATION

`harness threat-model packages/arc-agi-3-chatgpt` (a real, shipped MetaHarness example
targeting ChatGPT, not Claude Code) prints `Allowed tools: 0, Denied tools: 0` even though
`packages/arc-agi-3-chatgpt/.harness/mcp-policy.json` declares a 17-unique-tool, 3-role
`allowedTools` map and no `.claude/settings.json` exists at all. Confirmed by direct CLI
invocation before any code change, both via `harness threat-model` and `harness mcp-scan`.

## OBSERVATION

`packages/create-agent-harness/src/threat-model.ts`'s `buildThreatModel()` computes
`allowedTools`/`deniedTools` only from `settings?.permissions?.allow`/`.deny`
(`.claude/settings.json`). `packages/create-agent-harness/src/mcp-scan.ts` never reads
`policy.allowedTools` either (only boolean knobs). Repo-wide `grep -rn "allowedTools"`
outside `threat-model.ts`'s own interface finds exactly one real-world JSON instance
(`packages/arc-agi-3-chatgpt/.harness/mcp-policy.json`) and zero consuming code. An
independent architecture-review subagent pass confirmed (via `host-config.ts` lines
109-266) that 7 of the other 9 supported hosts (codex, hermes, openclaw, copilot, opencode,
github-actions, prime-agent) have no flat per-tool allow/deny concept on disk at all.

## INFERENCE

This is the CWE-636 ("Not Failing Securely / Failing Open") anti-pattern: an unhandled
condition (no flat permission data) produces a confident-looking but fabricated `0`
("nothing is allowed") instead of surfacing or disclosing that the format wasn't
inspected. The MCP spec itself names this risk class ("scope inflation blindness"), and
arXiv:2507.06250 measured it at scale across 2,562 real MCP servers.

## HYPOTHESIS

Given a generated harness directory whose MCP tool surface is declared only via
`.harness/mcp-policy.json`'s role-keyed `allowedTools` map, with no `.claude/settings.json`
`permissions` block present, when `buildThreatModel()`'s `allowedTools`/`deniedTools`
fields are changed to `number | null` (null + an explicit "N/A — role-scoped policy"
message in that case), then `harness threat-model` stops fabricating a `0`, subject to (a)
Claude Code's existing flat-count behavior and its genuine `0` semantics stay
byte-identical, (b) the already-correct boolean/verdict logic is untouched, (c) zero
regression in the existing suites, (d) the live CLI smoke test against the real
`arc-agi-3-chatgpt` fixture flips from `0/0` to the new `N/A` line.
