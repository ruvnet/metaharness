# Host-Adapters SOTA Report — 2026-08-24

TL;DR: MetaHarness's `packages/host-*` codegen keeps re-exposing the same bug
class — a spec field interpolated unescaped into generated structured
output — one new site per Dream Cycle night. 2026-08-14 fixed it for hermes
YAML mapping-keys; 2026-08-19 fixed it for github-actions bash/YAML and
explicitly disclosed three more unfixed sibling sites. Tonight's research
confirmed all three are real (with executable repros: js-yaml, Python
`tomllib`, and real `bash -c` execution), plus a fourth in `host-rvm`'s
generated shell installer that is the most severe of the batch — genuine
remote-code-execution the moment a user runs the generated script, not just
config corruption. Fixed `host-rvm` tonight (smallest, cleanest, highest-
severity single-file candidate); the other three are disclosed, not fixed,
to keep tonight's diff reviewable — five of the last five Dream Cycle PRs
are still sitting unreviewed and unmerged, so scope discipline matters more
tonight than breadth.

## MetaHarness Current Capability
10 host adapters emit native config from one `HarnessSpec` via 3
independently-maintained codegen paths meant to stay in parity (ADR-027).
An architecture pass tonight found the root cause of the recurring bug:
ADR-027's byte-parity guarantee was **downgraded, not enforced** — its own
2026-06-15 correction admits the parity test was never written — and the
one thing most sensitive to per-path drift, string-escaping helpers, has
**zero shared implementation** across 10 hosts × 3 paths. `yamlKey` is
copy-pasted 3× (acknowledged in code comments); `tomlEscape` exists as two
independently-authored copies, applied inconsistently even within one file
(`host-codex` escapes TOML *values* but not the table *header*). A shared
`@metaharness/codegen-safety` package is the right long-term fix — ADR-027's
own rejection of code-sharing was scoped to the whole stateful renderer
(fs/child_process/witness-signing), which doesn't apply to pure escaping
helpers — but that's multi-package, cross-ADR work, not tonight's diff.

## Hypothesis
Given `host-rvm/src/index.ts`'s `installScript(spec)`, which interpolates
`spec.name` unescaped inside two double-quoted bash strings (`rvm-loader
guest boot --partition "${spec.name}"` and the following `echo` line) —
double-quoting does not stop `$(...)`/backtick command substitution — when a
`shellDq()` helper (escapes `\`, `"`, `$`, backtick) is applied at both
sites, then a name containing shell metacharacters, reaching the exported
function directly (bypassing the CLI/web-UI's `validateHarnessName`
kebab-case gate, the only thing preventing this today), should no longer
execute injected commands when the generated `install-rvm.sh` runs, while
every existing benign name produces byte-identical output. Subject to: zero
regression in the existing 39-test suite, no change to `tomlEscape` or
`partitionToml` (already safe — confirmed independently), diff materially
under 300 lines.

## Adversarial Critique
Two independent critic rounds — the first would have shipped a materially
incomplete fix without the second:
- **Round 1: REJECT.** Confirmed `shellDq()` sound (bypass attempts via
  $()/backtick/quote-break/double-backslash all neutralized) and the two
  intended sites fixed — real `bash -c` repro: marker file created
  pre-fix, not created post-fix. But found an unrelated gap: `installScript()`'s
  and `partitionToml()`'s raw `'# ... ' + spec.name` comment-header lines
  have no quoting to escape into — a bare newline alone breaks out, no
  `$()`/backtick needed. Reproduced RCE against the round-1-fixed code via
  real bash execution (marker created). Also verified: JSON emission
  (`wasmGuestJson`, capability-table) safe via `JSON.stringify`; no ADR-027
  mirror-path break (host-config.ts/scaffold.ts never emit
  `install-rvm.sh`); new tests causally real, not vacuous (independent
  stash-and-rerun).
- **Round 2: ACCEPT.** Independently reproduced the round-1 gap is now
  fixed — `commentSafe()` (collapses CR/LF runs to a space) neutralizes LF,
  bare-CR, CRLF, and a TOML-section-injection payload, all via real bash
  execution / TOML-shape assertions. Re-swept the whole file for any
  remaining raw `spec.name`/`description`/`systemPrompt` site (found
  none). Confirmed the 2 new tests pin exact behavior, not vacuous. Noted
  3 non-exploitable control-character edge cases (NUL, VT/FF, Unicode
  line/paragraph separators) for the record — empirically inert in this
  bash/TOML/JSON context, not disclosed-but-unfixed gaps.
