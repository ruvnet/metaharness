## Hypothesis

Given three real, disclosed, critiqued trust-boundary fixes to `verifyReplayBundle`/`gateReExecutes`
(#205, #231, #255) that are semantically compatible but git-conflicting (each rewrites the same
region against a different stale base), when hand-merged (union of all checks, none dropped) into
one diff against current main, then the combined suite should pass with zero regression to any
honest bundle, while a fresh independent critic finds zero NEW exploitable gaps — subject to: (a)
every new check additive/opt-in by payload key, (b) no existing test weakened, (c) all 7 real
committed `ReplayBundle`s stay PASS. (The critic DID find one new gap — parents/generation binding —
unanticipated by the hypothesis; closed and re-verified below as a disclosed amendment.)

## Adversarial Critique

An independent critic (fresh session, no authorship context) reviewed the consolidated diff.
Initial verdict: **ACCEPT-WITH-CAVEATS**, with a working exploit — `BOUND_KEYS` did not bind
`parents`/`generation`, so two genuinely-signed commits could be spliced into a fabricated chain via
unsigned fields, defeating "reconstructs contiguously" with every check (incl.
`sealedFieldsAuthentic`) reporting PASS. Also noted, separately: `verifyReceipt` trusts a receipt's
own embedded key with no bundle-level trusted-key allowlist — pre-existing, not regressed, flagged
as a distinct future gap, not fixed tonight.

**Fixed, not just disclosed**: `parents`/`generation` added to `BOUND_KEYS` and the signed payload,
with a regression test reproducing the exploit, verified non-vacuous by remove-then-restore. NOT
re-reviewed by a second fresh critic pass (honesty note, ADR-250) — time went to closing and
independently verifying via exploit-then-fix testing, matching 2026-08-31's "commit 2" precedent.
