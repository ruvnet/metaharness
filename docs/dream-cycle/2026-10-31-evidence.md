## OBSERVATION

`packages/avo/src/crypto.ts`'s `canonical()` is a separate, independent
reimplementation of the same canonicalization algorithm as
`packages/flywheel/src/receipts.ts`'s `canon()`. The latter was hardened
against two gaps on 2026-10-16 (#406, unbounded recursion depth) and
2026-10-21 (#423, NaN/Infinity/-Infinity collapsing to the same `"null"`
token as real `null` under plain `JSON.stringify`). `canonical()` carried
both gaps independently, unaffected by either fix, because it is not a
shared import. PR #438 (2026-10-26, open/unmerged) ported the same hardening
to two *other* sibling duplicates (`avo/flywheelGate.ts`,
`turn-credit/receipt.ts`) and its own independent critic disclosed
`crypto.ts` as a third, previously-unknown duplicate — deliberately left
unfixed that night to keep the PR small.

## INFERENCE

The fix closes a real tamper-evidence collision (a non-finite value could be
silently substituted for `null` in a signed `ActionReceipt`/
`VariationCheckpoint` field without detection) and a real crash vector
(unbounded recursion depth) in code that is actually exercised by every
real AVO self-evolution run — a materially higher-value target than the two
siblings already ported in #438, which are additive gate mirrors with no
production caller yet. Independent adversarial critique (fresh subagent, own
repro) confirmed correctness and completeness within `packages/avo`, and
surfaced two *additional*, previously-undisclosed sibling duplicates:
`packages/horizon/src/checkpoint.ts` (`verifyCheckpoint()` has no try/catch
at all — worse than avo's pre-fix state) and `packages/harness/src/receipts.ts`
(ADR-047 hash-chained receipt log). Both are classified as HYPOTHESIS
(a disclosed, not-yet-measured candidate for a future night), not DECISION.

The critic also surfaced one disclosed, not-fixed caveat: `operator.ts`'s
live hot-path call sites (`sha256(this.options.invariants)`,
`transitionHash(...)` inside `transition()`) are not wrapped in try/catch,
so a non-finite value reaching them now throws and aborts a run instead of
silently signing a corrupted receipt. Reviewed realistic sources of such a
value (`ProtectedInvariants` is static config; every division in
`archive.ts`/`repository.ts`/`supervisor.ts` is explicitly guarded; the one
unguarded division, `swebench.ts:116`, feeds a benchmark report, not a
signed receipt) — real-world likelihood judged low, but the asymmetry is a
genuine, disclosed trade-off (fail-loud on data-integrity vs. silently-sign-
corrupted), not silently left undiscovered.
