# Security-Adversarial SOTA Report — 2026-10-03

TL;DR: Closes the most severe disclosed-not-fixed item from PR #362 (2026-09-28, unmerged):
`packages/darwin-mode/bench/swerebench/budget-watchdog.mjs`'s `--ceiling`/`--pid`/`--interval` flags were
parsed via bare unary `+`, so a malformed value silently coerces to `NaN`. Since `NaN >= x` and `x < NaN` are
both `false` in JS, this doesn't just weaken a spend-cap flag (#362's fix elsewhere) — it silently and
permanently disables a **SIGTERM kill-switch** meant to stop a runaway real-money LLM-benchmark process when
the in-process `--max-cost` (unreliable for Opus, per the script's own header) doesn't. A malformed `--pid` is
worse than inert: the script still prints `target exited or breached — done`, looking like a clean, completed
run. A malformed `--interval` degrades into an uncapped busy-poll against OpenRouter. Fixed with a 20-line
fail-closed `numericArg()` helper, byte-identical on every valid input. 7 new tests (0 prior), 4/7 fail
non-vacuously pre-fix, 0 regressions in 665 darwin-mode tests, $0 spend.

## Hypothesis

Given `PID`/`CEILING`/`INTERVAL`, each parsed via bare unary `+` with no finiteness check, when each routes
through `numericArg(flag, fallback)` (throws a named error on non-finite input; the `Infinity` "no cap"
sentinel still passes), then a malformed `--ceiling` can no longer disable the kill-switch, a malformed
`--pid` can no longer produce a false "armed and completed" exit, and a malformed `--interval` can no longer
degrade into a busy-poll — subject to: every valid invocation stays byte-identical, zero live spend in tests,
the new test is CI-wired per `check-runner-coverage.mjs`, diff under ~150 lines across 2 files.
