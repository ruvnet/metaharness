## Security review (STEP 15)

The fixed gap is itself security-relevant: `avo/flywheelGate.ts`'s `canon()` output feeds real
`edSign`/`edVerify` signature bytes and `sha256hex()` manifest-hash binding in the ADR-271 AVO→gate
promotion contract; `turn-credit/receipt.ts`'s feeds a tamper-evident credit-receipt digest. Pre-fix,
a NaN/Infinity-for-null field swap in either package could produce a byte-identical canonicalized
string to a legitimately-null-valued payload, which — combined with a replay/verification path that
compares canonicalized strings (as `canonEquals`/`sealedFieldsAuthentic`-style checks do) — could let
a tampered numeric field escape detection without needing the private signing key. No new capability
or scope is granted by this fix; it is strictly a narrowing (more inputs rejected, none newly
accepted). No MCP/tool-authority surface touched.
