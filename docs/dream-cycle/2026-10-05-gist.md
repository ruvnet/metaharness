# Generator-Genome SOTA Report — 2026-10-05

TL;DR: MetaHarness's `recommendPlan()` (behind `harness genome`/`metaharness score`'s repo-readiness
verdicts) picks one of 8 static "archetypes," each hardcoded `mcp: 'local'` or `'remote'` — **none ever
'off'**. `plan.mcp === 'off'` was structurally unreachable for ANY repo, even with zero real MCP signal,
silently breaking 3 downstream consumers whose own doc comments and tests expect 'off' to be reachable:
`resolveAgentTopology()`'s security-agent gate (always added 'security'), `scoreMcpRisk()`'s `surface:
'off'` branch (dead), and `recommendedMode` (always "CLI + MCP"). Same "seam built + unit-tested but zero
reachable production call site" class this repo's own ADR-278/279 name — a new instance, in genome
scoring rather than darwin-mode/flywheel. Fixed by deriving effective MCP mode from real repo signal
instead of the archetype's static default. Live CLI proof on a plain zero-MCP-signal TS SDK repo:
`mcp_surface` `local_default_deny`→`off`, `agent_topology` drops `"security"`, `toolSafety` 95→100,
`recommendedMode` `"CLI + MCP"`→`"CLI"`. 627/629 tests (+5, 0 regressions), 3/3 new assertions fail
non-vacuously pre-fix.

## MetaHarness Current Capability

`harness genome <repo>` and `metaharness score <repo>` both build a `HarnessPlan` via
`analyze-repo.ts::recommendPlan()`, then derive MCP-risk/security/mode badges from `plan.mcp`. The
8-entry `ARCHETYPES` library (same file) hardcodes each archetype's MCP posture; `mcp-server-harness`
is the only one requiring real MCP signal (`requiredSignal: 'hasMcp'`) and is the only one with
`mcp: 'remote'` — the other 7 are all `mcp: 'local'`, unconditionally.

## Hypothesis

Given a repo-readiness analysis (`harness genome` / `metaharness score`) for a target repo with zero
real MCP signal (no `.mcp.json`, no MCP-related manifest/README text, no MCP server registered in
`.claude/settings.json`), when `recommendPlan()` is applied, then the resulting `HarnessPlan.mcp` should
be able to report `'off'` — and downstream, `resolveAgentTopology()` should not add `'security'` purely
from the MCP branch, `metaharness score`'s `recommendedMode` should report `'CLI'`, and `harness
genome`'s `mcp_surface` should report `'off'` — subject to: (a) a repo that DOES show real MCP signal,
or whose winning archetype requires MCP (`mcp-server-harness`), is unaffected; (b) this is a
reporting/scoring-only change — it must not alter what a scaffolded harness actually ships, since
`index.ts`'s `scaffold()` call hardcodes `mcp: 'local'` independently (line ~626) for the generated
harness's own self-referential MCP server; (c) 0 regressions across the full `create-agent-harness`
suite.
