# Host-Adapters SOTA Report — 2026-11-09

TL;DR: `host-claude-code`'s `mcpAddCommands()` silently dropped `McpServerSpec.env`
(per-server environment variables — typically API keys/credentials a spawned MCP server
needs to authenticate) for stdio servers, while every sibling host adapter already projects
it. Fixed for the stdio branch, with a round-1 rejection and round-2 ACCEPT from an
independent critic who ran everything against the real, locally-installed `claude` CLI
(v2.1.319) rather than trusting string-equality tests alone — round 1's naive "add `--env`
everywhere" also-fixed the http-transport branch, which round 1 itself then caught as
broken (`--env`'s variadic parsing swallowed the URL positional with no `--` separator) and,
more fundamentally, discovered that `claude mcp add --transport http` never stores `env` at
all regardless of placement. Round 2 instead disclosed that no-op for http servers rather
than emitting a flag the real CLI silently ignores. Also disclosed, not fixed: a kernel
regression the ledger had claimed was already fixed (it wasn't — the merge never happened),
and an sdk enum-validation gap.

## MetaHarness Current Capability

Host adapters (`packages/host-{claude-code,codex,copilot,opencode,openclaw,hermes,prime-agent,github-actions,rvm,pi-dev}`) each project a generic `HarnessSpec` onto that host's native config/CLI format. `McpServerSpec.env?: Array<[string,string]>` (kernel-js `types.ts`) carries per-MCP-server environment variables. `host-codex`, `host-copilot`, `host-opencode`, `host-openclaw`, `host-hermes`, `host-prime-agent`, and `host-github-actions` all read and project `s.env`. `host-claude-code`'s `mcpAddCommands()` built the `claude mcp add` install-script line from `s.command`/`s.url`/`s.name` only — `s.env` was never read, so a spawned (stdio) MCP server that needs a credential via env silently lost it, specifically and only when targeting Claude Code. (Whether `host-codex`'s existing, already-shipped `--env` on its own `--url` branch is itself meaningful against the real `codex` CLI was out of scope tonight — not re-litigated, flagged only as a parallel question for a future night.)

## Hypothesis

Given a `HarnessSpec` with a stdio (command-based) MCP server definition that includes
`env`, when that spec is projected by `host-claude-code`'s `mcpAddCommands()`, then the
generated `claude mcp add` line should include `--env KEY=VALUE` flags for every entry and
the real `claude` CLI should persist them — subject to: (a) byte-identical output for the
existing no-`env` path and for the http-transport path; (b) env values pass through the same
`shellQuote()` escaping as other interpolated fields; (c) `--env` is never emitted where the
CLI's variadic parsing could swallow a following positional argument; (d) a url-based
server's `env`, which the real CLI does not support, is disclosed rather than silently
dropped or emitted as a no-op/broken flag. Frozen before implementation; revised once after
round-1's own adversarial critique falsified the "apply --env uniformly to both branches"
sub-claim with a live-CLI repro — the hypothesis's safety/disclosure clauses (c)/(d) were
added in response, not relaxed to fit a result.

  disclosed no-op comment line when `env` is set. Re-verified live: a stdio server's `env`
  now round-trips through `claude mcp add` into `~/.claude.json`'s `mcpServers.<name>.env`
  correctly (1 and 2-entry cases, spaces preserved); the http branch's primary line is
  byte-identical to pre-fix and still never carries `env`, matching the real CLI's actual
  behavior. 40/40 pass in the package (0 regressions on the 36 originally-passing). `tsc
  --noEmit` clean.
- Downstream: `create-agent-harness`'s `scaffold-e2e.test.ts` (the only in-repo consumer of
  `host-claude-code`) 14/14 unaffected; full `create-agent-harness` suite 703 passed / 2
  pre-existing skips (0 regressions), across 54 files.
- Blast radius confirmed via `grep -rn mcpAddCommands packages --include=*.ts`: only

- `npm audit --omit=dev`: 0 vulnerabilities.
- Independent adversarial critic, round 2 (fresh subagent, own live-CLI reproduction,
