# Flywheel-Promotion SOTA Report — 2026-11-26

TL;DR: The promotion gate's own re-verification path (`replay.ts` → `sequential.ts`) silently
accepts malformed per-item evidence instead of failing closed, contradicting the exact ADR-235
guarantee the code's own comments describe. Fixed with a 6-line type guard + regression tests.

## MetaHarness Current Capability
`packages/flywheel` runs candidates through `runFlywheelGenerations`, gates promotion with a frozen
4-clause `meetsPromotionRule` (optionally composed with anytime-valid sequential e-value testing,
`sequential.ts`), seals Ed25519-signed lineage receipts, and lets anyone independently re-verify a
bundle with `flywheel replay` without trusting the original run (ADR-235: "trust the gate re-run, not
the logged verdict"). A separate `production-gate.ts` path adds pre-registered comparison families,
fixed-alpha allocation across generations, and strict per-field `Score` validation
(`validProductionScoreDomain`) before anything is trusted.

**Signed, independently replay-verifiable promotion receipts do not exist in any shipped agent
framework surveyed.** Only early-stage IETF drafts and a single bachelor's-thesis prototype touch
this. This reads as a genuine open gap, not a deliberately avoided complexity: per arXiv:2607.13104
("Self-Improvements in Modern Agentic Systems," 14 Jul 2026), the field is still moving "from
research prototypes to deployed systems" — few shipped systems both self-modify *and* ship candidate
lineages that a second, untrusting party must later re-verify. MetaHarness's flywheel is
methodologically stricter than every competitor surveyed on this axis, at the honest cost of the
speed DGM-style unbounded autonomy buys.

## Hypothesis
Given a sealed `Score` whose `itemWins` field is array-shaped and length-matched but contains
non-boolean elements or a sparse hole (reachable via `replay.ts`'s independent re-verification of an
untrusted `ReplayBundle`, or via a live `Evaluator` that doesn't return a clean dense `boolean[]`),
when `pairedOutcomesFromItemWins` (sequential.ts) builds `PairedOutcome`s from it,
then it should return `undefined` (degrade to the base rule) rather than either (a) silently
producing a spurious concordant/discordant classification that distorts the promotion e-value, or
(b) throwing uncaught in the two call sites (`run.ts`'s live loop, `replay.ts`'s gate re-execution)
that have no try/catch,
subject to: (a) the already-tested empty/non-array/length-mismatch guards stay byte-identical;
(b) `replay.ts`'s `isCompleteScore` / live-loop behavior for already-valid dense `boolean[]` inputs
is unchanged; (c) the fix stays inside `pairedOutcomesFromItemWins`'s own "defense-in-depth,
return-undefined-never-throw" contract.
