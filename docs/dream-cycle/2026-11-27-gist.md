# Darwin-Evolution SOTA Report — 2026-11-27

**TL;DR:** `metaharness learn`'s real holdout promotion verdict (`evaluatePromotion()` in
`packages/darwin-mode/bench/swebench/gepa/learn.mjs`, plus its byte/behavior-preserving
TS port `promotion.ts`) has a bare strict-inequality `emptyPatchImproves` clause
(`cand.emptyPatchRate < seed.emptyPatchRate`). Once a seed's holdout empty-patch rate
reaches its floor (0 — no class-3/exploration-loop failures left), no candidate can
ever satisfy `<`, permanently locking promotion on that clause even when the candidate
ties the floor while being strictly better on both other axes (gold-resolution,
cost/resolved). The identical bug class was already found and fixed in
`packages/flywheel/src/gate.ts` (PR #306/#307, 2026-09-11) via a `baselineAtFloor`
tie-carve-out; `learn.mjs`'s structurally identical clause was never hardened the same
way. Fixed in both files, in lockstep, mirroring the existing pattern exactly.

**Why the "None" rows aren't just gaps:** LangGraph/AutoGen/CrewAI/Claude Agent SDK all
treat harness evolution as an ecosystem/vendor-tooling concern (LangSmith, Foundry,
DSPy integrations, community repos), not a core library feature — a deliberate
division of labor, not an unsolved problem. The one framework that *does* own
promotion-gate design end-to-end (GEPA) explicitly avoids the exact bug class found
tonight: it keeps floor/ceiling ties alive on the frontier rather than locking them
out with bare strict inequality. MetaHarness's own gate should match that design,
not fall short of it.

## Hypothesis (frozen before implementation)

Given a GEPA holdout evaluation where the seed genome's empty-patch rate has already
reached its floor (0 — no class-3 exploration-loop failures), when `evaluatePromotion()`'s
`emptyPatchImproves` clause is changed from a bare strict inequality to a floor-tie-aware
check (mirroring `flywheel/gate.ts`'s `baselineAtFloor` pattern: a tie at the floor
satisfies the clause; off-floor behavior is byte-identical), then a candidate that ties
the seed's floor empty-patch rate while not regressing gold-resolution and not worsening
cost/resolved should be correctly promoted instead of being permanently rejected —
subject to: (a) off-floor (seed.emptyPatchRate > 0) behavior is unchanged from before,
(b) the fix lands identically in both `learn.mjs` and its TS port `promotion.ts`
(ADR-228's declared behavior-preserving-port invariant), (c) the other two clauses
(`goldNoRegress`, `costPerResolvedNotWorse`) remain unchanged as backstops, so a
floor-tie alone — without also being non-worse on both other axes — still cannot promote.
