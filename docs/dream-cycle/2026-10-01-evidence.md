## OBSERVATION

`packages/flywheel/src/multigeneration-proof.ts` (`verifyMultiGenerationEvidence`,
merged in PR #358 on 2026-09-27, zero prior Dream Cycle review) compares
floating-point deltas — computed as `(wins/attempts) - (wins/attempts)`, an IEEE-754
double subtraction of two division results — against `DEFAULT_MULTIGEN_POLICY`'s
frozen numeric thresholds using strict `<`/`>=` at four sites (plus a fifth sibling
in `capabilityImproved`'s `costWin` branch), with no epsilon tolerance.

## MEASUREMENT

`node -e` integer search over `attempts ∈ [10,200]` found 542 (parentWins, childWins,
attempts) triples where the true mathematical delta equals `minImproverYieldDelta`
(0.05) exactly but the IEEE-754-computed value renders strictly below it. Concrete
instance: `attempts=20, parentWins=2, childWins=3` → `3/20 - 2/20 ===
0.04999999999999999` in Node v22.22.0.

Pre-fix (`git stash` on `packages/flywheel/src/multigeneration-proof.ts` only, test
file unstashed): `packages/flywheel/__tests__/multigeneration-proof.test.ts` new test
fails non-vacuously with exactly `['gen1:improver_yield_not_improved']`; the other 8
tests in the file are unaffected (no collateral breakage). Post-fix: 9/9 in the file,
144/144 package-wide (`npx vitest run` in `packages/flywheel`), `tsc --noEmit` clean,
`npm run build --workspace=@metaharness/flywheel` clean. Zero downstream importers of
`multigeneration-proof.ts` outside `packages/flywheel/` (`grep -rln` across all
`packages/*/src` and `packages/*/__tests__`, independently re-confirmed by the
adversarial critic).

## INFERENCE

The strict comparison makes `DEFAULT_MULTIGEN_POLICY`'s documented "frozen thresholds"
(ADR-318: "child successor yield exceeds parent successor yield by at least 5
percentage points") non-deterministic at the exact boundary, contradicting the
module's own stated guarantee — a generation that earns exactly the policy-mandated
minimum lift can be spuriously rejected, purely as a function of which integer
win/attempt pair produced a mathematically identical delta.

## HYPOTHESIS (frozen before the fix, see gist)

Given a `GenerationEvidence` whose improver-yield delta (or primary delta,
relative-cost-reduction, or control-primary-margin) is mathematically exactly at a
`DEFAULT_MULTIGEN_POLICY` threshold, when `verifyMultiGenerationEvidence` evaluates
it, then the verdict must be identical regardless of which integer (wins, attempts)
pair produced the delta, subject to: (a) existing passing/failing cases unaffected,
(b) the epsilon tolerance stays far smaller than any policy threshold, (c) 0
regressions.

## DECISION

**ACCEPT.** Fixed with a shared `meetsThreshold(value, threshold)` comparator
(`THRESHOLD_EPS = 1e-12`) applied to all five threshold-comparison sites in the
function. Independent adversarial critic (fresh subagent context, no access to this
session's reasoning) returned ACCEPT-WITH-CAVEATS: independently reproduced the
pre/post-fix test counts via its own `git stash` cycle, confirmed the fix is complete
(5 of 5 sibling comparisons, none left undisclosed), confirmed zero downstream blast
radius, confirmed no reward-hacking (no existing threshold value changed, no
assertion weakened, no gold data touched), and flagged that the initial `EPS = 1e-9`
was ~4500x looser than the real float-noise floor needed — EPS was then tightened to
`1e-12` (still ~4500x the noise floor, ~1e4x smaller than the smallest policy
threshold) in direct response, and the full suite re-verified green after the change.
One cosmetic nit the critic raised (a no-op `atBoundaryAttempts` variable in the new
test) was also fixed.

## REJECTION (candidates considered, not selected)

- Confirmation-set digests not bound to content (ADR-318 already half-discloses this
  limitation; a real fix requires a content-commitment redesign, out of scope for a
  small patch) — disclosed in gist, not fixed.
- `requireAllControls` as a caller-overridable policy flag (default is safe; only a
  risk for a hypothetical non-default caller) — disclosed, not fixed.
- Hardcoded reviewer `verdict: 'ACCEPT'` payload / no reject representation enabling
  reviewer-shopping — real design gap, but fixing requires a new verdict type and
  solicitation-count semantics, bigger than tonight's scope — disclosed for a future
  `security-adversarial` night.
- `-Infinity` sentinel in `relativeCostReduction` leaking unflagged into `derived[]`
  when `baseline.costPerWin === 0` — deliberately not selected to avoid a 3rd/4th
  consecutive night on the "non-finite value silently flows into evidence" bug shape
  already hit 2026-09-27 (#360, weight-eft) and 2026-09-28 (#362, darwin-mode bench
  scripts) per STEP 1.1's duplicate-direction rule; disclosed instead.
