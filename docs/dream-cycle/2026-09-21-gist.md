## Hypothesis

Given a `ReplayBundle` whose `lift_curve` contains at least one point with a negative `primary` (a
legitimate case: a PnL-style benchmark, or a root-only honest-null run below zero — nothing in `types.ts`
or `lineage.ts` prevents this), when `metaharness flywheel graph <bundle>` is invoked, then the command
should render a bounded ASCII bar (clamped to `[0, 32]`) instead of throwing `RangeError`, subject to: (a)
byte-identical output for any bundle whose primaries are all non-negative, (b) no change to `lineage.ts`'s
lift-curve computation itself, (c) a non-vacuous regression test covering the negative-primary case.
