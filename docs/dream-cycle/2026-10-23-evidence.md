## OBSERVATION

- `packages/create-agent-harness/src/mcp-scan.ts`'s `scanMcp()` computed
  `mcpEnabled` from exactly 3 surfaces: `.harness/mcp-policy.json`,
  `.mcp.json`, `.claude/settings.json`'s `mcpServers`.
- `packages/create-agent-harness/src/threat-model.ts`'s `buildThreatModel()`
  delegates `mcpInUse` directly to `scanMcp().mcpEnabled`.
- The CLI (`npx metaharness <name> --host <X>`) can scaffold 5 other hosts
  that register MCP servers in their own native config files: codex
  (`.codex/config.toml`), hermes (`optional-mcps/<name>.json`), openclaw
  (`.openclaw/openclaw.json`), copilot (`.vscode/mcp.json`), opencode
  (`.opencode/opencode.json`). None of these was read by `scanMcp()`.
- A 2026-10-18 dream cycle (#413/#414) made the *generator* always stamp
  `.harness/mcp-policy.json` at scaffold time whenever any of these native
  formats is populated — but the *scanner* itself never independently
  checked them.

## MEASUREMENT

- Live repro (pre-fix): scaffolded `--host codex`, deleted
  `.harness/mcp-policy.json`. `.codex/config.toml` had a real
  `[mcp_servers.smoke-codex-test]` entry (command=npx, real args). `scanMcp()`
  returned `{ mcpEnabled: false, worst: 'info', findings: [{id:'mcp-disabled', ...}] }`.
  Reproduced identically for hermes, openclaw, copilot, opencode.
- Post-fix (first draft): same 5 hosts correctly flipped to
  `mcpEnabled: true, worst: 'high'` — EXCEPT openclaw, which stayed
  `mcpEnabled: false` (wrong path checked: top-level `openclaw.json` instead
  of the real `.openclaw/openclaw.json`). Found live by an independent critic
  agent, not by this session's own first-pass testing.
- Same first draft: a directory with `optional-mcps/README.md` (no real
  server registration) incorrectly returned `mcpEnabled: true, worst: 'high'`
  — a false positive. Also found by the independent critic.
- Post-fix (corrected): all 5 native hosts + the no-MCP `rvm` host
  re-verified live; both critic-found bugs fixed with regression tests.
- `cd packages/create-agent-harness && npx vitest run`: 627→641/643
  (+14 new tests, 2 pre-existing skips, 0 regressions). Red proof: with only
  the source fix stashed, exactly the 5 new positive-detection tests fail
  non-vacuously; all negative/no-surface tests pass trivially (vacuous but
  correct) both before and after.
- `npx tsc --noEmit -p packages/create-agent-harness`: clean, both before

- `npm audit --omit=dev --audit-level=high --json` (repo root): 0

## INFERENCE

- The gap was real and live-reachable, not theoretical: any harness
  scaffolded before 2026-10-18, or with its policy file deleted/hand-edited,
  or with a native MCP config added by hand outside the generator, would
  have a live, completely unflagged, ungoverned MCP server for any of the 5
  native-host formats.
- The fix's correctness depends on matching each host's REAL CLI-emitted
  shape exactly (not the shape the dedicated `@metaharness/host-*` package
  would emit if called directly — these two code paths can diverge, as
  openclaw's wrong-path bug and hermes's `.yaml`-vs-`.json` divergence
  between `host-hermes` and the CLI's own `host-config.ts` both demonstrate).
  Self-testing against the diff's own fixtures was insufficient to catch
  this; live-scaffolding the real CLI binary and an independent critic were
  both necessary.
- `threat-model.ts`'s own `verdict`/`exitCode` computation does not
  escalate off `scanMcp()`'s `worst` field — confirmed independently by the
  critic on a live fixture (`scanMcp` → `high`, `buildThreatModel` →
  `clean`/exit 0, same directory). This is a separate, pre-existing bug
  (not introduced or masked by tonight's fix) already diagnosed and fixed
  in open PR #400 (2026-10-13, issue #399) — which is currently
  `mergeable_state: dirty` against current `main`.

## HYPOTHESIS (frozen before implementation, STEP 3.3)

Given a harness directory where MCP is registered only via a native host
format and `.harness/mcp-policy.json` is absent, when `scanMcp()` is
extended to independently detect codex/hermes/openclaw/copilot/opencode's
real native registration files, then `mcpEnabled` escalates to `true` and
`worst` to `high` (`no-policy`), subject to: (a) zero false positive on a
directory with no real registration (including a stray file in
`optional-mcps/`); (b) zero regression on hosts with no native MCP surface
(`rvm`); (c) the full existing suite stays green; (d) `threat-model.ts`
inherits the fix with no separate change.
