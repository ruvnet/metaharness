# Darwin-Evolution SOTA Report — 2026-11-12

TL;DR: `DARWIN-SHIELD-BENCH`'s own acceptance gate "Champion beats every baseline on fitness"
(`packages/darwin-mode/src/security/bench.ts`) compared `champion.breakdown.fitness > baseline.breakdown.fitness`
as a bare point estimate for all three fixed baselines (B0 static-only, B1 LLM single-pass, B2 fixed-agent) —
directly contradicting ADR-155's own Champion-promotion rule ("the champion genome must beat the previous
champion **and all baselines**... **with statistical certification**"). A second, separate gate already did
this correctly with a paired seeded bootstrap (`decidePromotion`/`bootstrapDelta`, lower95 > 0 + zero
unsafe-output regression) — but only for B2, "the previous champion". B0 and B1 never got the statistical
treatment ADR-155 itself claims every baseline receives. Fixed by routing all three baseline comparisons
through the same, already-imported `decidePromotion` machinery.

## Hypothesis

Given `DARWIN-SHIELD-BENCH`'s acceptance gate "Champion beats every baseline on fitness"
(`bench.ts`, originally `baselines.every((b) => champion.breakdown.fitness > b.breakdown.fitness)`), when
each baseline comparison is routed through the already-imported, already-tested `decidePromotion`
(paired seeded bootstrap, lower95 > 0, zero unsafe-output regression) instead of a bare point estimate,
then the gate should require real statistical certification for B0 and B1 exactly as it already does for
B2 — matching ADR-155's own documented claim — subject to: (a) the existing default scenario
(population:16, cycles:50, seed:0) continues to pass every gate; (b) zero regressions on darwin-mode's
existing suite; (c) no change to any corpus data, fitness formula, or other gate's logic. Frozen before
implementation, confirmed via live `git stash`-isolated repro before and after.
