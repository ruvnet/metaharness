# flywheel-promotion SOTA Report — 2026-10-11

TL;DR: `@metaharness/flywheel`'s ADR-317 `IndependentReviewPacket` (evidence-only,
worker-reasoning-free packets for independent reviewers of a promotion
candidate) ships with a `packetDigest` that is a **plain, unkeyed SHA-256** —
it proves a packet wasn't mutated after hashing, but *nothing* proves who
assembled it. ADR-317 discloses this itself as an accepted "Negative"
consequence, and the module has **zero production callers** (confirmed by
grep across `packages/` and `apps/`). The package already has the fix
pattern in production elsewhere: `multigeneration-proof.ts`'s
`ReviewerAttestation{reviewerId, receipt: PromotionReceipt}` +
`validAttestation()` binds a reviewer's verdict to a trusted public key via
the existing Ed25519 `Signer`/`verifyReceipt` infra (`receipts.ts`) — but
`review-context.ts` is the one module in the package that never adopted it.
Tonight adds an **additive, opt-in** signed variant
(`signIndependentReviewPacket`/`verifyIndependentReviewReceipt`) using the
exact same pattern, with zero changes to the existing unsigned path.

## MetaHarness Current Capability

`packages/flywheel/src/review-context.ts` (ADR-317, status: Proposed):
`prepareIndependentReviewPacket`/`verifyIndependentReviewPacket` build a
deterministic, tamper-evident, worker-reasoning-free evidence packet —
bounded tokens/digests, dense-array/null-prototype input snapshotting
(closes TOCTOU-via-getter/Proxy), allowlisted evidence kinds, byte/item
budget, expiry, `authority:'none'`. 20/20 existing tests pass. Zero
production callers (grep-confirmed). `packetDigest` is unkeyed —
ADR-317's own "Trust boundary" section states this outright: "Anyone can
mint a packet that verifies."

**Why so much "None":** this is a genuine, currently-unmet-demand gap, not a
quietly-solved problem — evidenced by a wave of *external* third-party/
standards efforts (the IETF draft itself, several small unaffiliated npm
packages claiming Ed25519 receipt chains) patching around the frameworks
rather than the frameworks shipping it themselves. Reviewer-evidence
isolation specifically (hiding an evaluatee's own reasoning from the human
reviewer, per ADR-317's collusion-mitigation motivation) is the least
addressed dimension found anywhere; GEPA's architecture is the literal
opposite design choice. MetaHarness's packet concept is genuinely
differentiated — even unsigned.

## Hypothesis

Given an `IndependentReviewPacket` built by `prepareIndependentReviewPacket`
for an independent reviewer of a flywheel-promotion candidate, when the
packet is additionally signed with the package's existing Ed25519 `Signer`
(mirroring the already-shipped `ReviewerAttestation`/`validAttestation`
pattern in `multigeneration-proof.ts`) and checked against a caller-supplied
trusted-producer-key set, then a verifier must detect and reject (a) a
packet signed with an untrusted/unknown key, (b) a packet tampered with
after signing, and (c) an unsigned/forged packet with no valid receipt —
while a genuinely producer-signed, unaltered packet from a trusted key must
still verify `ok:true`; subject to: the existing unsigned
`prepareIndependentReviewPacket`/`verifyIndependentReviewPacket` path is
completely unchanged (zero production callers today, so zero migration
risk); no new dependency (reuses `receipts.ts`'s `Signer`/`makeSigner`/
`verifyReceipt`/`canon`); the new check fails CLOSED on any missing/
malformed receipt, never silently skips it.

## Recommended Next Steps

1. **Wire a real review runner** (ADR-317's own disclosed "Neutral" gap:
   "no runner consumes it yet") — build the actual reviewer-job launcher
   that materializes *only* referenced evidence from a verified (now
   optionally signed) packet and denies shared memory/peer surfaces. Bigger
   than one night; needs a product decision on where review dispatch lives.
2. **Bind `evidence[].sourceDigest` to real receipts/replay bundles**
   (disclosed by tonight's Deep Researcher): today a producer can
   self-report any `sourceDigest` with no cross-check against
   `receipts.ts`/`replay.ts` — even a signed packet doesn't prove the cited
   evidence traces back to anything real. Candidate for a near-future
   flywheel-promotion night (~100-150 LOC, new test file).
3. **`validate-bundle.ts` has no string/array-length bound** on untrusted
   `ReplayBundle` JSON (only numeric magnitudes are bounded) — a
   memory/CPU amplification gap in "the ONE fail-closed runtime boundary
   for untrusted ReplayBundle JSON." Disclosed, not fixed tonight
   (~15-25 LOC, mirrors `review-context.ts`'s own bounding style).
4. **5 evals-* packages' per-category policy overrides
   (`__typeOverrides`/`__subjectOverrides`/etc.) bypass the documented
   "never free text" genome-clamping invariant** — currently inert (no
   mutation class targets these keys today) but a live validation hole in
   every one of evals-sql/math/hle/extract/toolcall. Disclosed, not fixed
   tonight (~50 LOC total, same ~10-line pattern × 5 files).
5. `scripts/bench-baseline.mjs`'s CI regression gate silently `continue`s
   past any current-report metric with no matching baseline entry, with no
   log line — a renamed/new metric is never regression-gated until a
   manual `--update`. Small (~5 lines), disclosed not fixed tonight.
