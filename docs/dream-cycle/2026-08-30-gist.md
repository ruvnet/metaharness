## MetaHarness Current Capability

`genome-scorers.ts` exports 5 pure, I/O-free functions consumed by
`genome.ts`'s `buildGenomeReport()`: `classifyRepoType`,
`resolveAgentTopology`, `scoreMcpRisk`, `scoreTestConfidence`,
`scorePublishReadiness`. Their outputs feed a weighted `risk_score` and a
`ready`/`needs-work`/`blocked` verdict with process exit codes 0/1/2 — a
real decision surface, not cosmetic output. None of the 5 functions, nor
`genome.ts`'s blend/threshold logic, had any test file anywhere in the
package (confirmed: `find ... -iname '*genome-scorers*test*'` empty;
`grep -rl genome-scorers __tests__/` empty). Two other functions in this
same file already have real, disclosed bugs sitting in unreviewed draft
PRs: `scoreTestConfidence` (#229, 08-25) doesn't verify declared test
commands correspond to real test files; `scorePublishReadiness` (#200,
08-15) only credits typescript/rust language presence, not python/go.

## Hypothesis

Given the deterministic, exported scoring functions in `genome-scorers.ts`,
which feed `genome.ts`'s user-visible verdict and exit code, when a
dedicated vitest unit suite is added covering each function's boundary and
representative-input behavior, then the surface gains characterized
regression coverage (0 → 33 tests) without changing runtime output for any
existing caller, subject to: byte-identical `genome-scorers.ts` (pure
test-addition), 0 regressions in the existing 458-test package suite, and
every new test provably non-vacuous (fails against at least one seeded
mutant of its target function).
