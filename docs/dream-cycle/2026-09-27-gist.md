# Darwin-Evolution SOTA Report — 2026-09-27

TL;DR: Tonight's darwin-evolution rotation surfaced its candidate on the SCAN surfaces, not the DEEP
surface itself — no new gap was found in `@metaharness/darwin`'s evolve/score/promote loop tonight, but
`weight-eft`'s two numeric CLI-flag gates (`--params-b`'s 7-14B safety band, `--max-tokens`'s export

(CVE-2026-54235 confirms the exact shape is CVE-worthy elsewhere in ML tooling).

## Hypothesis

Given weight-eft's `assertTunableSize()` (`train.ts`) and `exportTrainingData()` (`export.ts`), which
derive `paramsB`/`maxTokens` via `Number(...)` with no finiteness check, when a malformed CLI value
(e.g. `--params-b abc`, `--max-tokens abc`) produces `NaN`, then both functions should THROW a clear
error naming the bad value instead of silently no-op'ing the safety-band check or silently exporting 0
rows, subject to: (a) every previously-valid numeric input behaves byte-identically, (b) zero existing
test regresses, (c) diff stays under 300 lines, confined to `packages/weight-eft`.
