# Dream Cycle 2026-11-17 — darwin-evolution: GEPA's class-6/class-4 failure-classifier precedence bug

**TL;DR:** In 2026 the published SWE-bench-failure-taxonomy literature treats "ran out of
step budget" as a dimension orthogonal to "wrong fix" (Grade B, two independent sources below).
MetaHarness's own GEPA executor-genome classifier (ADR-228 §5.3, `classifyFailure`) conflates
them: whenever `goldPatchFiles` is known — the real production case — a budget-exhausted
trajectory that touched the right file is always mislabeled "wrong-fix" (class 4) instead of
"budget-exhaustion" (class 6), because the wrong-fix check ran first and class 6 was dead code
behind it. Fixed by reordering the two checks; non-vacuous before/after test proof in both the
TypeScript port and the canonical `.mjs` source `evaluate-genome.mjs` actually imports.

## MetaHarness Current Capability

`@metaharness/darwin`'s `gepa/metric.ts` (+ its canonical pre-port source
`bench/swebench/gepa/metric.mjs`, which `evaluate-genome.mjs` actually calls) already implements
a 7-way failure taxonomy (`FAILURE_CLASSES` 0–6) with per-class mutation hints (`MUTATION_HINTS`)
that feed GEPA's reflection-LM prompt as Actionable Side Information (ADR-228 §5.2) — ahead of
upstream GEPA, which has no such structure (Grade A above). But `classifyFailure`'s precedence
order meant class 6 ("budget-exhaustion… reach the edit earlier") was unreachable whenever
`goldPatchFiles` was supplied (the only real production shape); such trajectories always got
class 4's hint ("require reading surrounding context and re-running tests before submit")
instead — the wrong mutation direction for a budget problem. This is a plausible mechanism behind
`LEARNINGS.md` §64's Ornith-9B anomaly (14/15 instances exhausted the 20-step budget without
calling `submit`), independently flagged as a "banked runner-up" by last night's (2026-11-12,
#499/#500) darwin-evolution research but not yet implemented.

## Hypothesis (frozen before implementation)

Given a GEPA trajectory where `goldPatchFiles` is known and the executor landed ≥1 edit at the
gold file but exhausted its step budget, when `classifyFailure`'s budget-exhaustion check (class
6) is moved ahead of the wrong-fix check (class 4), then such trajectories are classified 6 not 4
— subject to: (a) quality invariant: all pre-existing class 0–5 assertions unchanged; (b) safety
invariant: only classification logic touched, never `computeInstanceScore`, gold data, or
thresholds; (c) regression threshold: 0 regressions repo-wide.
