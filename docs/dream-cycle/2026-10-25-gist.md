## MetaHarness Current Capability

`packages/create-agent-harness/src/analyze-repo.ts`'s `inventory()` and
`src/score.ts`'s `scoreTestCoverage()` each independently probe for a
`tests`/`__tests__`/`test` directory to decide whether a repo has verified
test coverage. Both previously stopped at `dirExists()`-style checks — "does
the directory exist" — never "does it contain anything." This feeds
`genome-scorers.ts::scoreTestConfidence()` (via `hasVerifiedTestFiles`),
`resolveAgentTopology()`'s `tester` role recommendation, and `score.ts`'s
"Test coverage" dimension (50/100 weight-15% credit) — all overstated for a
repo whose test directory is real but empty.

## Hypothesis

Given a repository whose `tests/` (or `__tests__`/`test`) directory exists
on disk but contains zero files anywhere in its subtree (freshly created,
emptied, or mis-scaffolded), when `inventory()` and `scoreTestCoverage()`'s
directory probes require at least one real file somewhere under the
directory (not just directory-entry presence), then `hasVerifiedTestFiles`,
`scoreTestConfidence()`, `resolveAgentTopology()`'s `tester` role, and the
"Test coverage" scorecard dimension should report unverified/low credit for
that repo — relative to current behavior, which reports verified/full
credit — subject to: byte-identical output for repos whose test directories
already contain real files (no regression), 0 regressions on the existing
genome-scorers/score/analyze-repo suites, and no LLM calls needed. Frozen
before implementation; not modified after.
