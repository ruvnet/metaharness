## MetaHarness Current Capability

`create-agent-harness` ships two CLIs: `metaharness` (scaffolder) and
`harness` (per-harness tooling — `doctor/secrets/validate/mcp-scan/sbom/
audit/threat-model/diag/compare/...`, dispatched via `subcommands.ts`).
10 host adapters exist (`host-claude-code/codex/pi-dev/hermes/openclaw/rvm/
copilot/opencode/github-actions/prime-agent`). Three of them have now had
a confirmed unescaped-name-into-generated-template defect: hermes (YAML
mapping key, #188, merged), github-actions (YAML/shell, #212, open 41
days), host-rvm (shell RCE, #224, open 5 days). No shared escaping utility
exists in `@metaharness/kernel` or anywhere in `packages/` — each fix has
independently reinvented the same `shellDq`/`commentSafe`/YAML-bare-vs-quoted
helpers. Tonight found the 4th instance, in `host-openclaw`.

## Hypothesis

Given `@metaharness/host-openclaw`'s `skillMarkdown()` and `installScript()`
functions, when a `HarnessSpec.name` reaching them through any caller that
bypasses the CLI's kebab-case `validateHarnessName` gate (direct SDK call,
web-UI, `--from-existing`) contains YAML- or shell-metacharacters, then the
generated `SKILL.md` frontmatter and `install-openclaw.sh` should render it
as an inert string rather than corrupting the YAML document or executing
injected shell commands — subject to: byte-identical output for any name
without those characters, 0 regressions in the existing 19-test suite, and
new regression tests must fail against pre-patch code (red/green).

## Adversarial Critique

Independent critic (separate subagent, not the candidate author) verdict:
**ACCEPT-WITH-CAVEATS**. Independently re-verified red/green by stashing
the fix and re-running only the new tests against pre-patch code (5/6
failed as expected — the critic's own repro, not a rerun of mine). Found
no weakened tests, no unfixed injection site within the touched functions,
no reward-hacking pattern, no regression risk for existing safe names.
One inherited (not new) caveat: `YAML_RESERVED_BARE` — copied verbatim
from host-hermes's merged `yamlKey()` — doesn't cover YAML-1.1 `y`/`n`
core-schema bools or hex/underscore-grouped numerics, so a handful of
exotic-but-benign names could still render bare and be type-coerced by a
strict loader. This is a data-fidelity gap, not an injection/RCE vector,
and matches already-merged precedent rather than introducing a new one —
not fixed tonight, noted for whoever eventually does the "extract the
shared helper" follow-up (see Recommended Next Steps).

The critic also independently confirmed, while checking whether #224
(host-rvm) was already on `main`, that it is **not**: `main`'s
`packages/host-rvm/src/index.ts` still has the raw, unescaped
`spec.name` in `installScript()`'s `--partition "${spec.name}"` and
comment/echo lines — no `shellDq`/`commentSafe` present. #224's fix
commits exist in git history but are not ancestors of `HEAD`. That RCE is
live on `main` right now, not merely "disclosed and waiting" — see
Recommended Next Steps.
