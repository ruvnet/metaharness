# generator-genome SOTA Report — 2026-09-05

**TL;DR**: `harness score`'s Publish-readiness dimension (`score.ts`) checked
`manifest?.host` for its 20-point "npx-runnable" bonus — a field that has
never existed on `HarnessManifest` (only `hosts: string[]` does). Every
scaffolded harness with a `bin` entry, however many hosts it declared,
silently fell to a 10-point fallback. A sibling scorer (`scoreRepoUnderstanding`)
had the mirror bug: `manifest.hosts` defaults to `[]`, and `[]` is truthy in
JS, so it credited "host(s) declared" even for zero hosts. Both fixed by
requiring `Array.isArray(manifest.hosts) && manifest.hosts.length > 0`.
2026 harness-quality research (below) reinforces why this class of bug
matters: presence-only checks systematically overstate scaffold readiness.
An independent adversarial critic re-derived the fix from scratch and
returned ACCEPT.

## Hypothesis

Given a scaffolded harness with a `bin` entry in `package.json`, when
`manifest.hosts` is a non-empty array, then `harness score`'s Publish-
readiness dimension should award the full 20-point npx-runnable bonus (not
the 10-point bin-only fallback it always fell to before), subject to: (a)
`bin` present with zero/no hosts still scores exactly 10, unchanged; (b) no
`bin` still scores 0 for this sub-dimension; (c) 0 regressions across the
554-test baseline suite; (d) new tests fail non-vacuously pre-patch.
