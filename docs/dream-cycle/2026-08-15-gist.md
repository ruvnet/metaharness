# generator-genome SOTA Report — 2026-08-15

**TL;DR**: 2026 practitioner tooling has spun "agent/repo readiness scoring"
into its own small category (Factory.ai, kodustech, agent-next, and others,
all launched Jan–May 2026) — and the one rigorous academic check of this
exact space (ETH Zurich's AGENTS.md study, Feb 2026) found a widely-rewarded
readiness signal actually *reduces* agent success, meaning nobody has
validated these heuristics against real outcomes yet, MetaHarness included.
Auditing MetaHarness's own `harness genome` scorer against that lens found a
concrete, previously-undiscovered instance of exactly this problem:
`scorePublishReadiness` credited only `typescript`/`rust` in its language
term, and `analyze-repo.ts` never synthesized a build command for
python/go — so a fully mature (CI-wired, tested, buildable) python or go
repo capped at 0.40 publish-readiness and could **never** reach `harness
genome`'s 0.75 `'ready'` threshold, independent of actual quality. Fixed,
independently critiqued, and backed by the module's first-ever dedicated
unit test suite (it had zero before tonight despite its own header claiming
"unit-testable without fixtures").

## MetaHarness Current Capability

`harness genome`/`score`/`doctor` and `metaharness score` (ADR-041) are
three parallel, unreconciled scoring subsystems over static file presence —
none learned, none calibrated against a scaffold-and-run outcome.
`genome-scorers.ts` backs `harness genome` with 5 pure, deterministic
functions; its own header calls itself "unit-testable without fixtures,"
yet had **zero dedicated tests** anywhere in the package before tonight —
confirmed by grepping every test file for each function name. That gap hid
tonight's finding: `scorePublishReadiness`'s language credit was a
`typescript`/`rust` allow-list, and `buildCommands` inference in
`analyze-repo.ts` (shared with `apps/web-ui`'s browser importer) generated
a build step only for those two languages, even though `python`/`go` are
first-class archetype languages (`data-pipeline-harness` requires python).
The sibling `metaharness score` command's taskCoverage dimension had an
analogous "measures the recommendation, not the repo" bug, fixed
2026-08-14 in #196/#171 — tonight's finding is the same failure class in
the neighboring `harness genome` surface.

## Hypothesis

Given `genome-scorers.ts`'s `scorePublishReadiness(profile, plan)` and
`analyze-repo.ts`'s `buildCommands` inference, when the language-credit term
is generalized from a `typescript`/`rust` allow-list to "any detected
language" and `buildCommands` gains a python (`pip install -e .` or
`pip install -r requirements.txt`) and go (`go build ./...`) entry, then a
fully mature python or go repo (CI-wired, tested, buildable, default-deny
policy) should score `publish_readiness >= 0.75` — reaching `harness
genome`'s `'ready'` verdict threshold, matching an equivalently mature
typescript repo — subject to: (a) typescript/rust scores do not regress,
(b) all 5 `genome-scorers.ts` functions gain direct unit coverage (zero
existed before), (c) no existing test is weakened, (d) the diff stays
materially under 300 lines.

   can still score 0.5–0.7 "test confidence."
