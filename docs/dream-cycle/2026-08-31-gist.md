## MetaHarness Current Capability

`packages/flywheel` is the host-agnostic promotion gate: a frozen conjunctive `PromotionRule`
(primary↑, no-op-rate↓, cost/win no worse, no safety regression, and — if supplied — a frozen
**anchor** suite must not regress, the anti-Goodhart guard). `receipts.ts` Ed25519-signs every
commit; `lineage.ts` is a DAG back to an immutable gen-0 root; `replay.ts::verifyReplayBundle`
lets an external reviewer re-verify with no trust in the producer, culminating in `gateReExecutes`
(ADR-235): re-run the frozen rule on *sealed* scores rather than trust the logged verdict.
`sequential.ts` adds an optional anytime-valid e-value layer (Ville's inequality) for repeated
peeking across generations.

`packages/avo` (ADR-251) is a separate, more autonomous variation runtime with its own conjunctive
gate and an external-gateway adapter (`flywheelGate.ts`, ADR-271) targeting a different repo's
`/v1/flywheel/gate`. ADR-251's own preregistered 100-task SWE-bench gate passed resolution
(+160%) and governance (zero violations, 100% replay) but **failed cost** (+97.7% vs a <50%
bound) — the ship claim stays honestly blocked, a good example of ADR-250's ladder in practice.

## Hypothesis

Given a `ReplayBundle` where an attacker with no signing-key access either (a) edits a
**PROMOTED** commit's unsigned `baselineScore`/`candidateScore`/`anchorScore` fields to values
that pass `gateReExecutes` despite not matching the signed `primaryDelta`, or (b) clones one
genuine receipt onto other fabricated commit ids to manufacture a fake multi-generation promoted
lineage from a single real promotion, when the receipt payload is extended to bind these fields
**and its own `id`/`target`/`verdict`/`primaryDelta`** to the commit it decorates, and a new
replay check verifies that binding before `gateReExecutes` trusts it, then `verifyReplayBundle`
should **FAIL** such a bundle where it previously **passed**, while every honestly-produced
bundle — including real bundles committed before this fix — continues to **PASS unchanged**.
Subject to: purely additive `ReplayVerdict` field, `meetsPromotionRule` untouched, diff kept
small, and no duplication of PR #205 (receipt coverage / id-verdict cross-check) or PR #231
(anchor reconstruction in replay) — this candidate composes with both, neither is required to
land first. (Part (b) of the hypothesis and its fix were added mid-session, after an
independent adversarial critic found part (a) alone insufficient — see Adversarial Critique.)

## Adversarial Critique

An independent critic sub-agent (not the candidate's author, no access to this session's own
reasoning) reviewed commit 1 in isolation. Verdict: **BLOCK** on the claim "closes the ADR-235
gap" — commit 1 alone stops naive score-splicing onto an *existing* signed commit, but the
critic found a more serious, unaddressed bypass: nothing bound a receipt's signed
`id`/`target`/`verdict`/`primaryDelta` to the live commit it decorates, so an attacker with no
signing key could clone ONE genuine receipt across many fabricated commit ids to manufacture a
fake multi-generation lineage from a single real promotion — `sealedFieldsAuthentic` (as
originally written) would not catch this, since the cloned receipt's sealed *values* still
matched the *copied* live fields. Commit 2 closes that specific bypass (test: "cloning ONE
genuine receipt onto a fabricated commit id … fails"). Two secondary findings, disclosed rather
than fixed tonight because they are pre-existing (not introduced by this candidate) and out of
tonight's small-diff scope:
- **MODERATE, tracked by #231**: `gateReExecutes` never passes `anchor` into `promotionRule()` at
  all, so the anti-Goodhart clause is never actually re-derived during replay — sealing
  `anchorScore` protects a value the re-run gate doesn't use yet. #231 already targets this.
- **MINOR**: `canon()`'s `JSON.stringify` base can collapse `NaN` and `null` to the same string,
  a theoretical collision reachable only if an evaluator ever emits `NaN` (not currently possible
  per the `Score` type, not runtime-enforced). Flagged, not fixed — low real-world exploitability.

**Honesty note (ADR-250):** commit 2 was written by this session in direct response to the
critic's finding and validated against a test reproducing that exact scenario, but — unlike
commit 1 — it was NOT independently re-reviewed by a fresh critic pass before this gist was
written; time/budget was spent closing the finding rather than re-running the adversary. That is
disclosed here rather than silently treated as re-verified.
