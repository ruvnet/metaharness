# Generator-Genome SOTA Report — 2026-11-25

TL;DR: MetaHarness's `genome`/`score` family of repo-readiness scorers is one entrant in a real 2026 "agent-readiness scanner" land-rush (AgentReady, agentlint, Factory.ai, others) — and the strongest fix available tonight wasn't a feature gap vs. those competitors, it was a dead constant quietly lowering our own READY bar. `scorePublishReadiness()`'s `+0.05 if (plan.policy.defaultDeny)` term fires on every single repo ever scored (every `HarnessPlan` construction hardcodes `defaultDeny: true` — no code path ever produces `false`), so it is not evidence about the repo being scored. Its practical effect: a repo with a detected language + a build command + CI wiring but **zero real test evidence** reached `publish_readiness` of exactly 0.75 — genome.ts's own `'ready'` cutoff — purely from this dead bonus. Removed the term; `'ready'` now genuinely requires test evidence.

## Hypothesis
Given `scorePublishReadiness(profile, plan)`, when `plan.policy.defaultDeny` is unconditionally `true` at every construction site (confirmed: `analyze-repo.ts:84`, `index.ts:642`), the `+0.05` term it gates contributes identically to every repo and is not evidence about that repo. Removing it should (a) not change relative ranking among repos, (b) correctly require real test evidence to cross `genome.ts`'s `publish_readiness >= 0.75` 'ready' threshold, (c) zero regressions, (d) zero LLM calls, (e) stay well under 300 lines. Frozen before implementation.

## Evaluation
- **Baseline** (`git stash` isolating only the source fix, new/updated tests kept): 7/38 genome-scorers tests fail, each off by exactly 0.05 — non-vacuous.
- **Candidate**: 38/38 genome-scorers tests pass; full package suite 763 passed/2 pre-existing skips (0 regressions); `tsc --noEmit` clean.
- **Live CLI**: this repo's own `publish_readiness` 0.90→0.85 (verdict unchanged: READY, it has real tests); synthetic zero-test fixture 0.75→0.70 (now correctly below the 'ready' cutoff).
- Blast radius: `scorePublishReadiness` from `genome-scorers.ts` has exactly one consumer (`genome.ts`) — confirmed via repo-wide grep; `score.ts`/`repo-scorecard.ts` define unrelated same-named local functions.
- Independent critic (separate spawned agent): **ACCEPT-WITH-CAVEATS**. Independently re-derived the call-chain proof, independently reproduced the 7/38 non-vacuous failure, ran the full suite + `tsc` itself, confirmed zero security-sensitive surface. Caveats: (1) **Correction** — the sole mechanism is `recommendPlan()`'s hardcoded `SAFE` policy constant (`analyze-repo.ts:330-351`); an earlier internal note also named `index.ts:642`, which is actually an unrelated scaffold-output object, not a second `HarnessPlan` constructor — corrected here, underlying claim unaffected. (2) `scoreMcpRisk`'s `!p.defaultDeny` (`genome-scorers.ts:86`) is the same dead-constant shape, currently harmless (folded into an OR with real flags) — disclosed, not actioned tonight to keep this diff to one conceptual change.
- Also refuted before implementation: the Deep Researcher's top-scored candidate (`scoreAgentUsefulness` allegedly 0-scoring 6/10 hosts) — live reproduction across 7 scaffolded hosts showed identical scores everywhere (`src/agents` is host-agnostic). Retained as a null result so it isn't re-proposed from the same code read.
