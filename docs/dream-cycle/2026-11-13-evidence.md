# Dream Cycle Evidence — 2026-11-13 (security-adversarial)

Durable OBSERVATION → DECISION record (STEP 13 classification).

## OBSERVATION
`packages/create-agent-harness/src/mcp-scan.ts`'s `scanMcp()` is the single
authoritative detector of risky `.claude/settings.json` grants
(`wildcard-tool-perm`, `unrestricted-bash-allow`, `risky-bash-allow`,
`no-secret-guard`, among others) that no `.harness/mcp-policy.json` field
can express. `threat-model.ts` already reuses `scan.worst`/`.findings`
directly (fixed 2026-09-03, #276). `score.ts`'s `scoreMcpSafety()` calls
`scanMcp(dir)` too (line 188, pre-fix) — but only consumes `.mcpEnabled`,
recomputing `mcpRisk` from policy-file booleans alone.

## MEASUREMENT
Built a real on-disk fixture: safe `.harness/mcp-policy.json`
(`defaultDeny:true`, all `allow*:false`) + `.claude/settings.json` granting
`mcp__*__*`. Pre-fix, the rebuilt `dist/harness-bin.js score --json`
reported `mcpRisk: "Low"`, `grade: "A"`, `exitCode: 0`. This is a real,
reproducible gap, not a hypothetical.

## INFERENCE
This reopens, through a sibling surface, the exact "averaging/masking away
an unsafe signal" failure mode the 2026-09-20 grade-cap fix (#336/#337)
was built to prevent: that fix caps the grade at 'C' whenever
`mcpRisk === 'High'`, but the cap can only fire if `mcpRisk` is computed
correctly — which it wasn't for settings.json-only risks.

## HYPOTHESIS (frozen before implementation)
Given a scaffolded harness whose `.harness/mcp-policy.json` reports safe
booleans but whose `.claude/settings.json` grants a HIGH/MEDIUM-severity
permission `scanMcp()` already detects (`wildcard-tool-perm`,
`unrestricted-bash-allow`, or `risky-bash-allow`), when `scoreMcpSafety()`
is changed to escalate `mcpRisk` to match those 3 specific finding ids
(reusing the already-computed `scanMcp(dir)` call), then `harness score`'s
`mcpRisk` badge and the existing grade cap correctly fire — subject to:
(a) a harness with no such finding is byte-identical; (b) the existing
policy-boolean risk computation is only ever escalated, never downgraded;
(c) zero regressions in `score-mcp-risk-grade-cap`/`score-mcp-detection`/
`genome-scorers*` suites. Deliberately scoped to exactly these 3 ids, not
`scan.worst` wholesale — several *other* scanMcp() findings
(`no-secret-guard`, `no-approval-gate`, `no-timeout`, `no-call-budget`) are
driven by policy fields or an absent settings.json this function doesn't
otherwise score, and `no-secret-guard` in particular fires merely from an
absent `.claude/settings.json` — escalating on those would have broken
every pre-existing fixture in the test file for a gap unrelated to this bug.

## DECISION

721→727/729 passed (+6, 0 regressions); `tsc` clean; `npm audit` 0
