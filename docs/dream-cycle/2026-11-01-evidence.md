MEASUREMENT (direct code read + live repro against built `dist`, tonight):
- `packages/weight-eft/src/train.ts:115-122` — `assertTunableSize(base)`:
  `if (base.paramsB < MIN_PARAMS_B || base.paramsB > MAX_PARAMS_B) throw ...`. Both operands of
  `<`/`>` against `NaN` are `false` in IEEE 754, so `paramsB = NaN` falls through with no throw.
- `packages/weight-eft/src/cli.ts:87` — `const paramsB = Number(flag(args, '--params-b') ?? '7')`:
  directly user-controlled; any malformed/empty `--params-b` value yields `NaN`.
- Both `sftConfig()` and `dpoConfig()` (train.ts:126/147) call `assertTunableSize` unconditionally
  — reachable even on the CLI's default **dry-run** path (`trainCmd`, cli.ts:116), not gated
  behind `--train`.
- Live repro against `packages/weight-eft/dist/train.js` tonight:
  `assertTunableSize({id:'x', paramsB: NaN})` → returns normally (no throw).
  `assertTunableSize({id:'x', paramsB: 32})` → throws correctly ("outside the tunable [1, 14]B band").
- `packages/weight-eft/__tests__/train.test.ts` has 3 cases for `assertTunableSize` (7B/9B accept,
  32B reject) — **zero NaN/non-finite coverage**.

INFERENCE: this is the exact same bug *class* (unguarded `<`/`>` comparison silently passing
non-finite input) as the already-ACCEPTed 10-17 `learn` fix, but a genuinely different file/
package/gate (`weight-eft`'s model-size safety band, not `learn`'s `$`-spend cap) and the named
09-22 disclosure, not yet closed by anyone.
