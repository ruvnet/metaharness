# flywheel-promotion SOTA Report — 2026-10-16

TL;DR: `@metaharness/flywheel`'s `canon()` canonicalization function — the single
choke point every signed receipt, replay check, and multi-generation proof in
the package routes through — recursed with no depth bound. A crafted
deeply-nested field smuggled into an untrusted `receipt.payload` (or an extra,
unchecked key on a `GenerationEvidence.child`/`.baseline` object) blew the
native call stack with an opaque `RangeError`, instead of the clean,
deterministic `{pass, failures}` verdict `verifyReplayBundle()` and
`verifyMultiGenerationEvidence()` are designed to always return. 2026's
dominant agent-tooling DoS pattern — a size/depth bound enforced on one axis
but not another — is exactly this shape (see citations below). Fixed by
bounding `canon()`'s recursion depth and converting every verification call
site that compares an untrusted value to fail closed instead of throwing.

## MetaHarness Current Capability

`@metaharness/flywheel` is a verifiable self-improvement loop: a frozen
conjunctive promotion gate (`meetsPromotionRule`), Ed25519-signed lineage
receipts, and independent replay verification that re-executes checks from
sealed inputs rather than trusting logged verdicts (ADR-234/235/274/279).
`verifyReplayBundle` and `verifyMultiGenerationEvidence` are both designed as
pure functions that accumulate failure reasons and return a structured
verdict — **never throw** — so that an external reviewer with zero trust in
the producer can always get a readable answer. That contract was violated by
one unguarded primitive (see Hypothesis).

No competitor in this set ships signed lineage + independent sealed-input
replay together; the closest analogs (AlphaEvolve's staged gate, the IETF
draft's signed-receipt idea) each have only half of flywheel's design. The
gap tonight closes is not architectural — it's a missing bound in one
canonicalization primitive, the same CVE-documented class (A-graded above)
that has hit MCP transports industry-wide in 2026.

## Hypothesis

Given a `ReplayBundle` or `MultiGenerationEvidence` containing a
`receipt.payload` (or an evidence field with an extra, unvalidated key) nested
deep enough to exhaust the native call stack, when `canon()`'s recursion depth
is bounded (failing closed with a clear, deterministic `Error` rather than
relying on the engine's native stack limit) and every verification call site
that compares an untrusted value swallows that error into "does not match"
rather than letting it propagate, then `verifyReplayBundle()` and
`verifyMultiGenerationEvidence()` continue to honor their documented contract
of always returning a structured verdict — subject to: (a) byte-identical
output for every legitimate, non-adversarial value; (b) 0 regressions on all 7
real committed `ReplayBundle` artifacts in this repo; (c) the depth bound
(64) stays well above any real payload's actual nesting.

## Recommended Next Steps

1. **Bind `review-context.ts`'s `evidence[].sourceDigest` to real receipts/
   replay bundles** — a signed `IndependentReviewPacket` still lets a
   producer self-report any digest with no cross-check against anything real
   (SLSA v1.2, A-graded above, is explicit that this must be verified
   downstream). Candidate for a near-future `flywheel-promotion` night
   (~100-150 LOC + new test file, per this scan's own re-derivation).
2. **Confirmed, unfixed on `main`**: all 5 `evals-{sql,math,hle,extract,
   toolcall}` packages' per-category `__typeOverrides`/`__subjectOverrides`
   JSON escape hatches bypass the documented genome-clamping invariant with
   zero per-field validation (exact sites: `evals-sql/src/genome.ts:136,148`
   and the ~10-line sibling pattern in the other 4 packages). Reachable at
   the deserialization boundary (any future receipt/checkpoint loader), not
   via the mutation proposer (which is safely restricted to 4 allow-listed
   targets today). ~10 LOC × 5 files.
3. **Confirmed, unfixed on `main`**: `scripts/bench-baseline.mjs:79`'s
   regression gate silently `continue`s past any current metric absent from
   the baseline (a renamed or newly-added metric is never regression-gated,
   no log line) — violates this repo's own fail-closed discipline and
   affects a hard (non-`continue-on-error`) CI gate. ~5-8 LOC.
4. **Flagged by tonight's independent adversarial critic**:
   `packages/avo/src/flywheelGate.ts:29` and `packages/turn-credit/src/
   receipt.ts:13` each ship their own separate, still-unbounded `canon()`
   duplicate of the exact primitive this candidate just hardened in
   `@metaharness/flywheel`. Out of tonight's scope (this diff touches only
   the flywheel package); worth checking whether either sibling
   canon-compares untrusted payloads the same way before deciding whether
   they need the same fix or can simply import `@metaharness/flywheel`'s
   hardened version.
