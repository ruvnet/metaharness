FunnelWheel · run report № 1 · for the team

A click funnel that proves its own lift.

We wired a five-stage funnel — ad click, landing, opt-in, checkout, upsell — into the MetaHarness stack. Darwin proposes one lever change at a time, the flywheel promotes only what clears a frozen gate on held-out traffic and a never-optimized-against anchor cohort, and every promotion ships with an Ed25519-signed receipt an outsider can replay. 01 · The stack

Three npm packages, one loop

Everything below is the published MetaHarness stack — installed from npm, not forked. The funnel is just the domain we pointed it at.

Harness factory metaharness

Mints the harness around the project and scores it: this example gets 100/100 tool safety at an estimated $0.048 per run (npm run score).

Mutation engine @metaharness/darwin

Proposes one lever change per candidate and picks variants with paretoFront over CVR × −CAC × revenue/visitor — deliberately compliance-blind, like a growth team chasing raw conversion.

Promotion loop @metaharness/flywheel

runFlywheelGenerations: frozen conjunctive gate, holdout + frozen anchor, Ed25519 receipts, lineage DAG, lift curve, and independent verifyReplayBundle.

02 · The loop

Run → measure → mutate → verify → promote

The traffic model is frozen; the funnel's operating policy — eight levers from headline strategy to checkout flow — is what evolves. Each generation re-bases on the previous promoted winner, so verified wins compound.

05 · The gate

96 candidates. 7 promoted. The gate held.

The proposer is intentionally greedy — its exploration pass never checks compliance. The frozen gate is where standards live, and it rejected 89 of 96 candidates.

The dark pattern that never shipped

The single biggest raw-CVR lever in the simulator is urgency: fake_countdown — a fake scarcity timer. Darwin proposed it 11 times across 11 generations (raw CVR up to 5.74% mid-run). The gate rejected it 11 out of 11 times with compliance_regressed. The shipped funnel converts 5.86× better with urgency: none — the lift is real, not extracted from users.

Why candidates were rejected

A candidate can fail several clauses; counts overlap. Compliance rejections are the gate doing its most important job.

Every candidate, CVR vs. CAC

● promoted ○ rejected × compliance-blocked
Down and to the right is better. Promotions ride the frontier; the × marks converted well and were rejected anyway.

06 · The proof

Don't trust us — replay it

The run emits a replay bundle. verifyReplayBundle checks the signatures, reconstructs the lineage to the gen-0 root, confirms no rejected candidate was smuggled into the chain, matches the pinned gate fingerprint, and re-executes the gate against each promotion's sealed scores. All six checks pass with zero trust in the machine that produced the run.

Reproduce it: cd examples/click-funnel && npm install && npm run evolve — ~2 seconds, deterministic, no network, no API key. Outputs results/summary.json and the signed results/replay-bundle.json.

Traffic is a seeded simulator (stamped SYNTHETIC in the bundle) so the loop is free and replayable. Pointing it at production means swapping one function — the simulator — for your analytics query and stamping the bundle LIVE. The gate, receipts, lineage, and replay stay identical.
